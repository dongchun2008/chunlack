# 空 Agent 客户端名单：关闭策略

## 适用范围

这是显式 `clientIds: []` 的兼容策略，不是自动接入或授权功能。保持已有供应商中立路由和 Ollama 支持，不修改模型配置或密钥。

| 配置 | 行为 |
| --- | --- |
| `discoveryOnly: true`，`clientIds: []` | 仅预接入发现，不允许 Agent 业务访问。 |
| `discoveryOnly: false`，`clientIds: []` | 允许正常初始化，但关闭全部外部 Agent MCP 业务访问；不会抓取 JWKS。 |
| `discoveryOnly: false`，非空合法名单 | 继续执行原有令牌、身份绑定、工作区、节点和细粒度授权校验；列入名单不等于获准执行。 |

`clientIds` 缺失、`null`、字符串、重复值等仍须拒绝；名单最多 32 项，不能复用真人登录客户端。关闭 OAuth 的旧版模式不因本次兼容改动获得额外权限。

## MCP-only 的最小配置差异

以下只是对已有完整配置的差异说明，不可作为完整配置覆盖现有文件；必须保留正确的 issuer、resource、JWKS、真人客户端和私有凭据设置。

```json
{
  "publicRuntime": {
    "nodeRestPublic": false,
    "agentOAuth": {
      "enabled": true,
      "discoveryOnly": false,
      "clientIds": []
    }
  }
}
```

应用与 HTTPS 入口的模式必须一致。配置在初始化时形成不可变快照；修改调用者对象不能打开入口，实际配置调整应走已批准的受控更新流程。

## 安全边界

- 空名单同时拒绝 OAuth 令牌和有效已配对节点令牌的公网 MCP 请求，不能回退到旧节点令牌路径。
- MCP-only 继续拒绝两个公网主机上的全部节点 `/v1` REST 路径；内部回环节点功能仍需原有认证。
- 首次初始化可以建立授权表和成员代次记录，但不会创建授权。
- 从非空名单改为空名单时保留已有授权记录和成员代次，但空名单期间不能凭它们访问。空名单不是永久撤销；恢复名单前须审查并撤销不再需要的旧授权。
- 新增 Muse、dots 或其他 Agent 仍需单独核对客户端、节点、工作区和允许范围，不能因发现接口可访问就视为已接入。
