# 外部 Agent 授权管理使用说明

状态：开发验证中，尚未发布到线上。以下操作说明供本功能通过验收并发布后使用；不要据此认定 Muse 老镇或 dots 玄玑已经接入。

## 这项授权解决什么问题

ChunLACK 需要同时确认三件事：外部客户端是谁、它代表哪个已绑定的真人账户、这个账户允许它操作当前工作区的哪个节点。

一个授权记录将账户 subject、Agent 客户端、工作区、节点、操作范围和有效期明确绑定。模型服务配置是另一层，创建授权不会配置模型、创建云端账号或放开节点的文件和命令权限。

## 使用前提

- 登录的是 ChunLACK 真人账户，并且在当前工作区具有“所有者”角色。
- 私有部署的 Agent OAuth 配置已完成验证并启用。
- 外部 Agent 使用单独批准的客户端，不复用真人登录或 Tailscale 客户端。
- 外部账户 subject 已通过明确的身份绑定关联到 ChunLACK 用户，不按邮箱自动合并账号。
- 当前工作区已经登记目标节点，该节点属于被授权账户；未撤销。暂停节点即使存在授权也不能领取新任务。
- 外部产品的协议和账户能力另行验证。存在授权记录不代表该产品已连接成功。

## 创建授权

1. 在页面顶部选中目标工作区，确认角色为“所有者”。
2. 打开“Agent 授权”。列表中的记录只表示已保存过授权，不保证当前仍能执行。
3. 填写 Pocket ID 账户的 `subject` UUID。这不是登录用户名，也不是客户端密钥。
4. 在已批准的客户端列表中选择对应 Agent 客户端，再选择当前工作区的目标节点。不要选择真人登录客户端。
5. 按需勾选操作范围。默认只有 `task.read`，有效期默认一小时。
6. 选择一小时、24 小时或七天的有效期。
7. 点击“创建授权”，核对页内确认中的账户、客户端、节点、操作范围和到期时间，再确认。

确认之前不会发送创建请求。等待确认或网络响应时，按钮会阻止重复提交。切换工作区、关闭面板或失去管理权限后，旧面板不应继续发起操作；后端仍会重新核验权限。

## 操作范围

| 范围 | 用途 |
| --- | --- |
| `task.read` | 连接发现和受授权任务的读取。正常发现流程需要它。 |
| `task.claim` | 领取分配给对应节点的任务。 |
| `task.result` | 提交对应任务的执行结果及协议允许的相关内容。 |
| `events.read` | 读取该连接可访问的事件信息。 |
| `events.subscribe` | 创建受授权的事件订阅；回调地址还须通过独立的安全策略。 |

授权范围与实际访问令牌范围取交集。这里勾选某项不能让范围不足的令牌自动获得权限，也不能绕过工作区成员资格、节点状态或任务归属检查。

## 外部 Agent 如何选择连接

统一 MCP 资源地址为 `https://agents.chunclaw.top/mcp`，不要在 URL 后添加工作区或授权编号。

完成受支持的授权流程后，客户端调用 `chunlack_connections_list` 获取当前可用连接，再在每次具体操作中显式填写所选 `grantId`。即使只有一项连接也不自动选中；不能因某项权限不足而悄悄改用另一项授权。

详细协议见 [连接路由说明](AGENT_CONNECTION_ROUTING.md)。本说明不提供密钥，也不要求把令牌粘贴进聊天、浏览器表单或仓库。

## 查询和撤销

打开“Agent 授权”可以查看客户端、节点、操作范围及是否已经过期。未过期也可能因成员资格变化、身份解绑或节点撤销而失效。

撤销时点击对应记录的“撤销授权”，核对客户端和节点后确认。撤销会使后续依赖该授权的操作和事件投递重新校验并被拒绝，但不能撤回已发出的数据，也不保证远端已执行的操作自动停止或回滚。

撤销一项 OAuth 授权不等于撤销该节点所有其他接入方式。例如，独立的旧式配对令牌仍按其自己的权限检查工作。如需停止节点的全部后续接入，应使用节点暂停或撤销功能，并核对仍在执行的任务。

## 常见情况

- 看不到入口：先检查当前工作区是否选中，以及真人账户是否为所有者。
- 面板加载失败：可能是该部署尚未启用功能、连接失败或权限变化。不要把失败当作“没有授权记录”。
- 没有可选客户端或节点：先完成受控配置及节点登记，不能在表单里临时填入未批准的客户端。
- 创建被拒绝：检查 subject 是否已绑定、节点是否属于该账户、客户端是否被允许、有效期及操作范围是否合法。
- 提示重复授权：不会自动覆盖或扩大原有权限；先核对原记录，确需改变时再明确撤销并重新授权。
- 令牌能登录但不能执行：真人登录成功、Agent 令牌签名有效、本地授权有效和任务执行成功是不同的验收环节。

## 接入成功的最终标准

必须实际证明外部 Agent 收到任务、使用其自身电脑执行、返回匹配的任务编号和随机校验码、提供原始证据，并由 ChunLACK 保存结果和回执。配置保存、连接发现成功、HTTP 200 或模拟执行都不能替代这一验收。
