## 原有边界保持

深度32、20000条目、最多1000个数据文件、数据合计64MiB、入口配置4MiB、拒绝链接／特殊文件／跨设备数据树／未知分配量／元数据漂移。任何超限都失败，不截断后当成功，也不自动提高上限。

使用原20秒远端进程组封套与35秒本地执行器。开始时只建立一个总截止时间；测量分配 `min(15秒, 原总窗口剩余－5秒)`，之后仅恢复原截止时间的剩余值，为结束基线与输出留时间。输入和源码加载发生在 Python 信号安装前，物理上限仍依赖外部20秒封套，不能把入口称为独立全程硬抢断程序。

如果开始基线失败，保护状态保持未知；结束基线失败不掩盖原读取失败。保留安全格式的关闭错误，以及 `raise … from None` 隐藏的有界因果链，最多8个附加节点并去重；不输出原始异常路径或任意对象，不重试 close。命令清理未知时拒绝成功，并由外部封套结束原进程组；不声称已取得内核级进程清空证明。

## 成功的含义

`accepted` 仅指 `data-and-ingress-component-only`：在原限制内，取得两次完整且相等的元数据观察，并完成前后基线和该次回执。它不代表：

- 候选实际占用已知或完整发布空间充足；候选占用仍为 null。
- 跨数据库应用一致性、真实备份或恢复已完成。
- 兼容证明、正式入口资源策略、运行权限或全系统隔离已验收。
- 正常写入导致的漂移就是数据损坏；漂移应记录并停止，不能自行停服务来通过检查。

数据与入口复制量来自既有保守模型，不是实际磁盘预留。整体容量仍需绑定实际候选分配量和其它必要开销。
