# 完整容量采集与兼容复验：本地准备方案

> **For agentic workers:** Use superpowers:executing-plans to implement the local preparation tasks below. No remote execution is authorized by this document.

**目标：** 补齐深度8截断后的完整元数据采集准备，以及数据库副本兼容复验的输入、顺序和拒绝条件；本轮只进行本地实现与回归。

**架构：** 复用已固定哈希的 `metadata_sizing.py`、`compatibility_inputs.py` 和原始完整证明验证器。新适配层仅输出数据备份组成部分和未启用的复验请求；不新增服务、调度器、数据库结构或授权系统。

**技术：** Python 标准库、现有测试及冻结的66文件产品候选；没有新依赖安装。

## 依据与现状

- [本轮只读预检](../../verification/2026-11-13-production-readonly-preflight.json)已消耗1/1连接额度，失败原因是146处深度8截断；该额度不复用。
- 57个已知源码摘要与257项依赖版本匹配；依赖完整指纹覆盖4462文件，但不是源码目录的穷尽枚举，也不是软件供应链证明。
- 查阅的4个历史发布目录各有6份控制器、3份原始摘要匹配本地冻结候选；不是已部署正式入口的绑定证明。4份所查兼容证明已过期，不能修改时间戳复用。
- [本地备份范围组合回归](../../verification/2026-11-13-backup-capacity-scope-parity-local.json)28项通过；未证明现网完整容量或一致性备份。

## 全局限制

- 本轮不连接 VPS、不新增 Linux 单元、不发布，不改凭据、授权或 Relay。没有 SSH 启动入口。
- 保留旧深度8采集器、冻结候选、失败目录、写锁与历史额度，不覆盖它们。
- 完整数据采集复用现有深度32、20000条目、1000个数据文件、数据合计64MiB、Caddy4MiB与15秒观察上限；遇到限制或错误就失败，不返回部分成功，不自动重试或放宽上限。
- 只读取路径与 stat 元数据，禁止读取业务文件内容；拒绝链接、特殊文件、跨设备数据树、未知分配量与观测漂移。两次元数据一致不等于应用一致性。
- 数据组成部分不包含候选占用。内部调用既有估算器时令候选占用为0，仅投影独立的数据复制量；不输出该次调用的总容量充分结论。候选占用未知时，完整发布容量仍为未知，绝不把0当实际候选上界。
- 兼容复验仍使用原完整验证器，不新增可伪造的“通过证明”生成器；不把本地合成账号、合成库或哈希比较当成原生证明。

## 本轮交付与回归

1. 新建私有容量投影适配层和失败优先测试：固定来源摘要、只调用一次、完整字段／类型校验、明确数据范围、错误不降级、禁止以局部容量放行发布。
2. 新建未启用请求生成器：绑定本地66文件清单及本次预检记录；显式列出缺失的生产输入、候选真实分配量和完整兼容证明，不能将已有过期证明改为新鲜。
3. 回归深层目录／复制范围测试，以及既有元数据、描述符、输入字节绑定和原完整证明验证器测试。测试只用本地夹具；不重跑无关应用全量，不启动模型或外部 Agent。
4. 独立只读复核；记录源码哈希、测试结果、未启用请求及剩余关键节点。通过后仅同步方案与脱敏记录，不提交私有实现或生产配置。

## 后续关键节点：需另行确认

### A. 完整数据元数据观察

建议单独批准一次只读观察，远端20秒／本地35秒、失败不重试、零 Linux 单元。固定目标为数据根 `/var/lib/chunlack-public`、入口配置元数据 `/etc/chunlack-public/Caddyfile` 与备份文件系统 `/var/backups`，沿用上述15秒内部遍历上限。

前后核对四项服务和配置摘要；遍历不读取业务内容、不创建备份、不执行发布。成功只消除“数据目录覆盖不完整”这一项，不替代候选分配量、应用一致性、权限来源或正式启动器验收。无法在原预算内取得完整结果就停止，保留明确失败。

### B. 生产输入与候选占用绑定

在受批准的准备范围内绑定实际候选源码／控制器、依赖、正式入口及20%候选策略，并测量候选的实际分配量。需要原始配置、环境和入口字节的独立摘要，以及工作区授权的完整结构指纹；密钥只通过现有私有机制引用，不进入聊天或 Git。

本地请求必须保留这些缺项。既有“数据组成部分”的0候选值不准用于正式总容量计算；实际候选及其它必要副本／元数据开销没有绑定时，不返回“空间充足”。10%现有入口不能由20%演练证明替代，历史目录也不能自动选作正式入口。

### C. 新鲜数据库副本兼容复验

待输入绑定后，另行申请一个兼容性复验单元；不是现在获批的额度。建议保持90秒、192MiB、20% CPU、Nice=10、CPUWeight=10、32 Tasks、零交换、隔离网络；所有子进程计入限额，失败即停、不重试。

沿用已验证的副本准备与应用启动驱动：仅准备阶段按批准范围只读取得逐库一致副本，在独占副本上执行原有候选／旧版启动顺序；业务进程为UID996/GID987、NNP及原有能力边界，不能以 root 跑业务。保留原数据、表结构、身份与授权指纹，验证私有节点访问及转发访问拒绝、干净关闭和写锁释放。

原完整证明需要：候选／旧版／配置／依赖／提交绑定，入口与环境原始字节摘要，完整授权／控制器指纹，真实身份及启动回执。证明最长有效期1小时，发布准备要求至少剩余5分钟；禁止延长旧证明、填造身份或将多个逐库副本标成跨库应用一致性快照。若需要改变顺序、策略、控制器或资源参数，先核对受影响演练证据，不能自动沿用旧结论。

### D. 正式发布与交付

完整容量、生产包绑定及新鲜兼容证明成立后，才提出维护方案。保留55秒前向／120秒总恢复预算、应用停止后的一致性备份、旧代码、配置及新写入保护；不删除遗留写锁，不动旧 LACK 与 Relay。

维护发布和真实模型预算分别确认；发布后仍须真人登录、语言与帮助、路由／研究、工作区隔离及持久化验收。玄玑安静任务路线与苏婳原生接入仍按独立目标验收，不能由容量或兼容回归替代。
