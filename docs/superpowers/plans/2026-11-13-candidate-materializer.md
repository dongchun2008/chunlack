# 候选目录与依赖物化实现方案

目标：把已通过本地验证的候选字节映射，写入新的独占候选目录，复制既有依赖并统计真实分配量，供后续实际输入兼容验证使用。

采用 Python 标准库；复用上一阶段组装结果、正式路径和依赖指纹记录格式，不新增调度器、服务或依赖安装。本阶段仅本地实现与合成回归，不连接 VPS、不新增 Linux 单元、不发布。

- 入口仅允许 Linux root，固定现有 `/opt/chunlack-public/current`、新的 `/opt/chunlack-public/staged-<tag>/current` 与 `/var/lib/chunlack-release-<tag>`。正式设置、证明及 claim 不生成。新目录已存在即拒绝，不覆盖或删除旧目录。
- 六个入口／控制器固定摘要、66 文件清单摘要和完整输入指纹先核对；释放目录文件保持 root:root 0600／0700，stage 为 root:987 0640／0750。依赖原有执行位保留。禁止不可信目录、符号链接父目录、特殊文件、跨设备和文件身份／元数据漂移。
- 复制 node_modules，不建立指向 live 的外部目录链接。保留允许的内部相对文件链接及其拼写；拒绝目录链接、越界、循环及不可解析链接。前后完整依赖指纹必须与原观测及实际副本一致。
- 全程使用同一有界 tick。读取文件用 NOFOLLOW、读取前后身份核对；独占创建目标、fsync 并重新读取核对。失败保留目录作为现场，不自动清理或重试。
- `st_blocks*512` 仅在字段存在且合法时统计，包括新目录和链接；候选占用不以源码字节数替代。完成后输出 candidate allocation，完整备份空间判定仍由原容量算法完成。
- 先写失败测试，再实现复制引擎及 Linux 适配层；本地合成文件系统验证逻辑、拒绝路径、部分失败保留和输入不变。Windows 无可用 WSL，不能把本地模拟元数据当 Linux 权限／分配量验收。
- 本地回归及独立复核通过后只同步本方案及脱敏记录。真实目标机准备、依赖读取权限和数据库副本兼容仍是后续关键执行范围。
