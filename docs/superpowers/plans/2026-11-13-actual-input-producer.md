# 实际输入准备进程本地集成

目标：将已验证的字节组装器和候选物化器接入一个只准备候选、不执行发布的固定输入进程。复用旧源码／配置读取器、原授权结构指纹、原控制器身份校验和原依赖记录格式。

本阶段只做本地实现与模拟回归。不连接 VPS、不新增 Linux 单元、不发布，不改凭据、授权或 Relay。真实目录创建、授权库只读查询及原生资源验证须在具体执行范围确认后运行。

## 实现

1. 先写失败测试，再实现纯流程：资源与身份核验→实际输入快照→冻结摘要核对→组装→入口材料摘要核对→再次资源核验→物化→最终完整输入／权限核对→脱敏回执。任何漂移或超时即失败，已写候选保留现场，不删除／重试。
2. Linux 适配层沿用固定三份配置的安全读取函数；环境正文只在内存参与摘要绑定，不物化为新凭据。源码、依赖、Node/Caddy 摘要必须和已接受观察匹配。入口材料与先前真实 Caddy adapt 的完整材料摘要匹配，不把复用该字节证据说成本轮重跑 Caddy/TLS。
3. 授权指纹调用原 `authority_fingerprint`：只允许既定 identity.db 的 mode=ro URI，检查数据库目录只读挂载，设置同一全程截止时间的 SQL progress handler。原完整表结构／索引／触发器及授权／epoch 表指纹均保留；不读取其它业务表、不注入合成记录、不写库。
4. 内核校验沿用正式入口原 `verify_controller_identity`，核对本次专用 prepare 单元的实际 cgroup、192MiB、20% CPU、Nice=10、CPUWeight=10、32 Tasks、零交换、NNP、0xeb 控制器能力、无继承／ambient 能力及只有 lo 的网络视图。一个90秒全程截止包含加载、写入、关闭与回执准备；不在阶段内重开计时。
5. 内部不查询服务、不连接 systemd 控制接口。外层既有执行器仍须核对四项服务及配置的前后基线、真实单元退出／进程清空和资源策略，才能接受原生执行。内部回执明确外层验证待完成；不声称新鲜数据库兼容或发布完成。
6. 本地测试覆盖身份失败先于私有读取／写入，配置、权限、源码和运行时漂移，超时、后置失败保留，以及回执不含原始配置／环境或用户标识。关联回归和独立复核后同步本方案与脱敏记录。

## 当前执行边界

该组件是候选准备进程，不创建 systemd 单元、不上传包、不启动 LACK/Caddy、不生成正式 settings／兼容证明。后续把已固定的进程接入既有外层执行器时，应先明确上传、独占目录、挂载及真实 DB 查询范围，再提出一个有限原生准备单元；不复用已消费的旧额度。

外层集成不得通过开放主机整个 `/var/lib` 或 `/opt/chunlack-public` 写权限来解决独占 mkdir。沿用已验证演练的私有父目录视图及嵌套只读绑定方式；原生退出和保护基线通过后，另以不覆盖的受限操作把两个新候选目录放到主机正式候选位置。此操作不切换运行中的应用。控制源码包、私有镜像父目录、结果及后续 settings/proof 占用，都必须纳入完整容量检查，不能只取物化器的部分分配量。
