# 实际候选输入组装：本地实现

目标：将已经固定的 66 个产品文件、正式入口与四份控制器，以及原始配置字节派生的材料，组装成可供后续原生兼容驱动使用的实际文件映射。复用既有 draft 和原门禁，避免另造配置／证明系统。

本阶段只用本地合成配置；不连接 VPS，不新增 Linux 单元，不发布，不改凭据、授权或 Relay。用户已要求持续推进并仅在关键节点确认；可逆本地实现、回归与既定脱敏同步属于现有授权。

1. 先写失败测试：精确来源清单、66 个产品字节、正式路径映射、缺失／额外／漂移文件拒绝、路径碰撞拒绝、原始配置保留、无环境密钥副本、无伪造证明或 settings.json。
2. 新建纯组装器。固定来源摘要后才加载既有 draft；固定完整载荷清单，检查所有源文件摘要、长度和相对路径，再映射为 release.py、launch.py、controllers/* 与 staged/current/*。不执行启动器、不解压外部归档、不触发文件写入或网络。
3. 输出 compatibility-inputs.json 及确切文件字节；其用途是传给未来的受限兼容驱动，不是正式 settings.json。保留原 settingsDraft、完整预期源码清单与私有配置摘要。依赖必须作为目标机上的完整候选副本另行复制与核验，不设置越界 node_modules 链接。
4. 实际组装一次本地合成输入，逐文件核对正式入口固定哈希和 required 集合：必须且只能缺少 settings.json 与原生 schema-compatibility-report.json。正式发布入口在这两项缺失时不能加载。实际测得的候选分配量、原生身份／网络／兼容回执不能在本地补零或伪造。
5. 完成定向回归和独立复核。同步本方案及脱敏结果，不提交私有实现、原始配置、合成材料或旧失败现场。

后续关键范围是目标机新独占目录准备、依赖副本的实际分配量与读取权限测量，以及绑定真实输入的新鲜逐库兼容验证。应在本地产物和驱动具体可审查后提出，不能把本次字节组装当成这些步骤已经通过。
