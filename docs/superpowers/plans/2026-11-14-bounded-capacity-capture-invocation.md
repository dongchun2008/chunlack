# Bounded complete-capacity capture

The accepted preparation still needs complete capacity and database-copy compatibility evidence. Its former failure-only capture allowance is ineligible because preparation succeeded. This plan itself authorizes no connection, unit or publication.

The final local candidate supersedes an unpublished draft, retained privately. Five runtime sources and a generic trusted-entry template are frozen together. The trusted caller captures and verifies the template before using it as literal code; the template verifies and executes the captured launcher buffer. Parent and SSH-child execution likewise use captured source bytes, never a validated path reopened for execution. The exact local directory and directory identity are part of a separate new one-shot approval.

The parent and SSH child share the launcher's absolute35-second deadline, with final-receipt/cleanup reserves. The existing owned-process executor and an own-process watchdog guard the outer entry. The SSH command retains the20-second remote timeout and original15-second metadata inner cap. Exclusive outer, parent and child-start records prevent repeats. Missing or copied-directory approval fails before a connection attempt.

The proposed one-shot read-only query covers:

- Four existing services before and after the query.
- Complete metadata for prepared source/control/results, release and stage directories; DATA and ingress metadata for backup sizing; free space and inodes. It does not read business database contents or run SQL.
- One fixed reservation JSON and five generated candidate files: candidate-config.json, compatibility-inputs.json, expected-code.json, Caddyfile.final and Caddyfile.loopback. Digests are bound to the accepted preparation and checked before/after metadata collection. Their bodies stay in private local evidence; runtime.env body is not collected.

Acceptance requires observed actual exit/EOF, confirmed owned SSH cleanup, consistent timing and exact source/worker/material bindings, followed by the original complete capacity/configuration/authority validation. Disk outcomes remain provisional accepted=false; the final launcher output plus actual exit are authoritative. No compatibility proof, business permission or release is created.

Relevant local tests cover synthetic success, missing/old/copied approval, source-path races, duplicate attempts, partial output, timeouts, cleanup/clock failures, material drift, stale/insufficient capacity and summary redaction. An isolated local watchdog process and actual missing-authorization entry are local evidence only, not native timing or SSH acceptance.

After local review and sanitized synchronization, request at most one new20-second remote/35-second local SSH query. Failure stops without retry. No Linux units or remote writes; do not change services, credentials, business grants, DNS, ports, Relay or old failure directories; no real model or external Agent calls.

Only after verifying returned capacity/materials should a separate database-copy compatibility unit be proposed. Fresh production configuration and full candidate/dependency digest checks are still required: metadata does not replace them. Production publication, consistent backup, recovery and live acceptance remain later gates.
