# 只读预检到候选准备的接线

复用已经验收的20秒远端／35秒本地只读预检，先把运行包和结果消费接好；不连接VPS、不新建单元、不发布。此前准备单元关键确认仍待答复，不因自动续行自行授权。

1. 固定旧预检runner、collector、packet、外层及传输摘要。仅在新派生entry加显式activationAuthorized=true检查，检查早于runner和SSH载入。旧文件和已用一次性标记不改，不复制旧approval。
2. 将完整预检结果与真实外层退出／完整耗时、内层摘要、SSH终态和清理、四项服务与配置前后基线、57源码／依赖／Node／Caddy及两个Caddy材料摘要核对。单独的accepted、HTTP200、缓存文件或summary不够。
3. 新预检packet仍须等于已冻结准备包的实际输入期望。拒绝超过5分钟／未来时间、缺少终态、失败清理和任一漂移；不重写历史时间戳，不把旧成功当新观察。
4. 输出仅为“准备前只读条件核对”，不会生成Native单元授权、兼容proof或生产ready。待关键节点确认后，另建一次执行目录使用已审版本；失败不重试、不扩额。
5. 本地失败优先测试、复核并生成未启用运行包，仅同步方案和脱敏记录。包内旧runner仍有原生CLI能力；意图开关不是安全沙箱。

## 2026-11-13 执行续记

用户随后明确允许连接VPS并确认下一步。新独占目录的一次20秒／35秒只读预检通过；随后运行一个受限准备单元，未发布。准备单元失败即停，未复用旧额度或重跑。

一次固定失败现场只读采集确认：worker报`producer_deadline`，同一Invocation的systemd终态为failed/failed、MainPID=0、ControlGroup为空、退出状态2。原控制器把这一合法失败终态再次判为身份错误，遮蔽了真实退出状态。

只在新本地派生模块修复终态识别：Id、Invocation及全部数字／状态校验保留；仅在MainPID=0且匹配精确终态组合时允许空ControlGroup。运行态、其他非空cgroup和异Invocation仍拒绝。六项新增及十六项原控制器回归通过；未修改冻结包或现网，也不声称解决了worker超时。

后续先在本地给准备流程补齐阶段耗时与失败阶段证据，按原时限定位超时来源；未经验证，不增加时限、不删除失败目录／写锁、不自动新增远端单元。容量、数据库副本兼容和生产维护仍未通过当前阶段验收。
