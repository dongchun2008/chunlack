# 准备超时的本地阶段诊断

既有一次原生准备已失败，日志只证明 `producer_deadline`，没有证明具体耗时阶段。本轮只做本地准备，不连接 VPS、不新增单元、不发布，不增加原 75 秒工作、80 秒运行及 90 秒单元预算。

1. 新建有界、纯内存阶段记录器。只记录固定阶段名称、调用次数、相对耗时与异常类型，不记录参数、返回内容或异常正文；不增加重试、文件、后台进程或网络。
2. 复用同一准备启动时钟。对实际 producer 的 context、snapshot、assemble、materialize、初始化及收尾设置计时，不改变调用顺序或任一校验；两个 snapshot 分别留证。
3. 仅从冻结包生成新的 entry 候选，嵌入固定摘要的记录器；原始包、源码及失败现场不改。失败回执保留原异常树，并附阶段证据；时钟异常不得产生成功退出。
4. 补齐计时、失败、时钟、容量、脱敏与真实 producer 组合回归，并独立复核。只同步脱敏记录。没有新原生结果前，不声称已解决超时或达到生产交付。
