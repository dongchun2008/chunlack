# 网页发起外部节点浏览试点

## 当前状态

已实现候选版本的网页入口及受限任务创建 API，Windows 实际打包 HTTPS 生命周期和完整回归通过。尚未升级 VPS 生产服务、尚未启用正式公网入口，也没有因此接通 Muse 老镇或 dots 玄玑自身的云端电脑。此说明用于后续候选验证与部署后的使用，不代表目前公网已经可用。

## 使用流程

1. 登录并选择正确工作区；所有者在“节点”登记执行节点。首个浏览试点只选择 `browser.public_read` 一项能力，范围为 `public`。节点不是模型服务。
2. 将一次性配对码通过已批准的安全方式交给对应节点，使用工作区绑定的配对入口。不要把配对码、节点令牌或网页密码发送给公共频道，也不要共用真人 Cookie 与节点 Bearer 凭据。
3. 在“节点”面板为未暂停、未撤销的专用浏览器节点点击“公开浏览试点”，阅读并确认页内提示。成员可发起，只读成员不可发起；只有所有者能管理节点。
4. 系统为所选节点建立 `https://example.com/` 浏览与截图任务，随机校验码及五分钟期限由服务端生成。网页只提交节点 ID，不能改成内网 URL、任意 shell 命令或其他权限范围。
5. 点击“查看任务进度”。执行节点需领取对应 taskId，用自己的执行能力完成操作、上传截图并提交匹配结果；不能把服务器抓图、模拟图片或 SDK worker 回答冒充 Muse/dots 自身执行。
6. 如需停止，任务面板选择“取消”并确认。远端未确认停止之前仍占用共享执行槽；撤销节点或重启服务不能凭空证明远端停止。

当前试点是公开网页浏览，不是通用 shell、文件或电脑操作授权。注册节点及 HTTP 2xx 均不构成真实外部 Agent 接入成功；“succeeded”也不等于人工验收通过。

## 受限 API

真人入口为 `POST /api/tasks`，只接受：

```json
{"targetNodeId":"工作区内的节点ID"}
```

由现有真人会话、工作区成员关系、Origin 和 CSRF 验证后，调用已有 scoped gateway 队列。返回 `201` 与 `{task: ...}` 状态元数据，不返回校验码、输入、租约或模型凭据。节点通过原有受限 REST/MCP 通道取得执行所需信息。

节点注册上限仍为整个平台五个，不是每个工作区五个。执行槽仍为全局一个，工作区等待上限仍为二十；五个注册节点不等于五个同时执行或五个模型 Agent 已完成协作。

## 已知缺口与安全边界

- 网页只对单一 `browser.public_read` 能力、单一 `public` 范围的节点展示按钮，与专用截图入口一致。目前创建 API 仍沿用 store 的包含式能力/范围检查，尚未统一拒绝混合能力节点；直接调用 API 可能生成不能走专用截图入口的任务。该边界已提出待修正，未将其标为交付通过。
- 结果状态可以在任务面板查看，但真人端逐任务证据/截图展示和人工验收闭环仍需补齐，不能用状态列表替代成果验收。
- 本轮没有完成真正的五模型 Agent 持续协作、Linux 当前新版本复验、正式证书/公网生产切换、真实模型或 Muse/dots 自身执行。旧数据归属及维护窗口、直接模型服务信息仍需现场确定；Open WebUI 不在范围内。

测试证据见 `docs/verification/2026-10-11-public-node-lifecycle.md`。整个系统的交付门槛仍按已批准总计划执行。
