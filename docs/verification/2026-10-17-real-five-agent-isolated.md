# 真实五 Agent 独立运行时验收

日期：2026-10-17。结论：Windows 独立运行时的五 Agent 两轮真实模型试点通过；整个平台尚未完成交付。

## 本轮实际完成

- 使用当前源码生成独立运行包，真实 HTTPS/WSS、临时数据库、三个合成真人账号、两个工作区；五个 Agent 在其中一个工作区执行。
- 两轮均实际观察到五个 Agent 的非空回复，并等待新增任务全部 completed、activeBranches 为零及模型 HTTP 请求结束。
- 两轮分别耗时 4728 和 4706 毫秒；成功试验共 10 次真实推理，10 成功、0 失败，最大同时推理数为 1。
- 所有 Agent 共用一个现有直接模型服务，模型为 `qwen38-27b-nvfp4`。这是五个逻辑 Agent 通过共享容量协作，不是五个独立供应商或五次并行推理。
- 三个账号完成测试登录；同工作区成员能访问模型视图，另一工作区的查看者被拒绝。没有进行真人长时使用或两个工作区同时生成的验收。
- 重启的仅是隔离运行时。重新连接后，两轮共 10 条回复的 ID 和内容哈希与重启前一致；这不证明未完成任务可以自动续跑。

## 实际路径与失败记录

本轮先从 VPS 使用现有 `onecat-direct` 配置复验：模型列表和一次短文本生成均返回 200，模型一致且内容非空。未通过 Open WebUI，也未修改模型配置、凭据或确认实际 GPU/推理引擎拓扑。

五 Agent 试验的前两次失败分别保留：

1. 首次在便携版 Caddy 校验阶段触及原夹具 10 秒上限，零推理请求，清理完成。后续只读 version 命令用时 2.023 秒；这个测量不能证明校验超时的具体原因，不能据此增加默认预算。
2. 第二次通过启动阶段，但 Windows 直连线上配置的模型地址未取得成功生成，代理记录 8 次失败，整轮失败。独立 Windows 模型列表检查发生 RemoteDisconnected，而 VPS 路径已返回 200。具体断开原因未确认，没有改 DNS、代理策略或证书校验。
3. 第三次脚本及全部预算不变，仅将测试模型传输改为临时本机回环 SSH 转发，沿用已核对指纹的 VPS 及其现有模型访问路径，取得上述通过结果。

临时转发只监听 Windows 的 `127.0.0.1` 随机端口，限定一个现有模型目的地址，设置 240 秒兜底关闭。没有在 VPS 新建监听或修改 Tailscale。试验结束后已关闭监听、线程与全部转发通道，测试 Node 进程退出 0。

## 生产共存与 Pocket ID

前后只读采样中，旧 LACK、Relay、公网应用、HTTPS 四项服务的 PID 和重启计数一致，均 active，真人健康接口返回 200；Relay UDP 40000 仍监听。没有重启生产服务、改客户端/授权/订阅，也没有测量真实 Relay 转发质量。

线上配置仍为 discovery-only，外部客户端名单为空。本轮 Pocket ID 公开发现文档返回 200，声明 S256 及签发者识别；没有声明 CIMD 或动态注册端点。因此下一步优先核对供应商界面的预定义客户端入口及准确回调，不将缺少声明等同于永久不支持，也不自动登记客户端。

## 复现材料与边界

已执行的脚本快照：[real-five-agent-20261017.cjs](../../deploy/public/acceptance/real-five-agent-20261017.cjs)。它依赖仓库测试夹具和已有便携 Caddy，只使用独立测试数据，不是生产负载工具。

需要显式提供 `CADDY_TEST_BIN`、`PYTHON`、`CHUNLACK_REAL_PROBE_BASE`、`CHUNLACK_REAL_PROBE_MODEL`、`CHUNLACK_REAL_PROBE_REPORT`。报告文件必须不存在，模型服务必须允许这次测试访问。脚本不配置 API 密钥，不建立 SSH 转发，也不会自动使用生产配置；地址及密钥不要写入 Git。若测试机不能访问模型地址，须先确认受控路径，不能盲目照抄 VPS 地址。
