## 实际覆盖与修正

真实旧表数据与活动 WAL 经完整迁移进入实际打包服务。三位测试用户在两个工作区保持会话，核验身份、角色、CSRF、真实 WebSocket 消息隔离和两个 Agent 完整一轮的主回答。分别经过本地 HTTP 与模拟云端 HTTPS 模型接口，模型请求保留研究原始来源，未包含另一工作区私有消息。

服务关闭和重启后消息仍隔离；退出登录撤销对应 WebSocket。原始研究 URL 和缺证标志仍保留。独立恢复副本在当前打包程序的私有旧兼容模式启动后读取到原历史，保留未知表且数据库完整性为 ok。原库、原 WAL 和原配置哈希始终不变。

真实失败诊断发现并最小修正两项应用问题：

- 旧 Memory 中只有 URL、缺少叙述文本的记录使召回 TypeError，导致 Agent 不能完成回答。四项回归中修正前 1 项通过、3 项失败；修正后 4 项通过。原记录不被删除或补造，只限制用于召回的条目类型与有效 Embedding。
- 私有旧兼容模式频道初始化不调用已有 SQLite 历史读取器，恢复库有数据但页面历史为空。实际恢复启动断言修正前失败，初始化接入已有读取器后通过；不改变多用户分支或公网访问权限。
