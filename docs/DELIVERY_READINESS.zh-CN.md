## 新接入对象怎么准备

1. **先选接入类型。** 只有推理 API 的机器登记为模型服务；会领取任务、操作工具并回传的程序登记为执行节点；要调用厂商产品自身的 Agent，必须使用其受支持的原生触发和结果通道。DGX Spark 可同时提供两种能力，但分别登记。
2. **模型接入。** 使用 provider 配置和显式 Agent 映射；只在私有配置中提供地址、模型名和密钥文件。保留 Ollama，不硬编码 1Cat，不复用 Open WebUI 的界面或凭据。先有界验证，再启用所需工作区授权。
3. **节点接入。** 优先复用 `sdk/agent-client.cjs`、现有网关和 MCP；按账号／客户端／工作区／节点／任务／租约限定能力。首次只授予单项能力，以独立任务编号和校验码验证执行、结果、附件持久化及人工验收。
4. **玄玑。** 下次先证明独立任务目的地和自身电脑能力，再进行最小临时授权试点。不得向日常对话粘贴任务日志、协议 JSON、进度或截图数据，也不得为继续开发而偷偷恢复已撤销授权。
5. **苏婳。** 作为新对象核对当前账号支持的认证、触发、执行和回传方式；尚未确认前保持待接入。不推断需要或不需要新 Key，不把旧 Muse Gadgets token 当作通用 Agent API 凭据，不把自建 worker 运行当作苏婳执行。
6. **验收结果。** HTTP 2xx／OAuth 成功／工具可见只是局部证据。要同时有原生任务活动、任务与校验码匹配、真实工具操作证据、ChunLACK 保存的结果和单独的人工验收；失败保留原因，不自动换执行者冒充成功。

本轮没有创建连接、节点、客户端、订阅、任务或授权，也不要求先开放新公网端口。

这些是后续执行顺序，不是本轮启动远端操作的许可。
