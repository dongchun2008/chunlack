## 身份与范围

用户确认：Muse 名为“老镇”，“初心”是用户通过其他渠道中转消息时的署名，不是另一个 Muse。

本轮通过用户已登录的 Muse 页面发送了两次能力核对问题，以及不含服务器地址、密钥或真实任务编号的接口摘要。只读问题明确禁止创建连接、读取凭据、配对、网络探测、安装和服务配置。没有部署 ChunLACK，也没有发起真实任务。

## 老镇报告的机制

| 项目 | 老镇提供的线索 | ChunLACK 当前判断 |
| --- | --- | --- |
| 自定义连接器 | `credentials.request_api_access` 注册 `custom.<provider>`，支持 API key 或 OAuth code 认证 | 有平台机制线索，当前账号接入未实测 |
| Bearer | 凭据 placement 可选 `bearer_header`，使用安全凭据存储和出站替换机制 | 不能把真实密钥写入 CLI、环境、对话或日志；替换链路未实测 |
| HTTP 请求 | 官方 skill 脚手架生成 workspace skill，CLI 使用 Python HTTP 库，并使用凭据替身 | 更像 skill 与 CLI 接入，不是已确认可直接导入 OpenAPI |
| JSON、业务头、204、二进制 | 老镇从普通 HTTP 请求代码推断这些可实现 | 机制可行线索，Muse 实际行为和限制仍待验证 |
| api_hosts | 最多 10 个裸域名，批准范围外出站拒绝 | 不应假定可把 tailnet IP 填入凭据主机白名单 |
| Tailscale | 终端使用官方 CONNECT 代理通道 | 不证明浏览器、连接器后端或凭据替换也走该通道 |
| 私网凭据注入 | 未找到安全凭据替换与 Tailscale CONNECT 组合的说明；MagicDNS 行为未知 | 是当前真实接入的关键阻碍，不能绕过 |
| 自动唤醒 | 未找到受支持的外部推送唤醒接口 | 未找到不等于明确不支持；先考虑用户手动启动单任务 |

老镇列出的内部依据包括 `~/docs/connectors.md`、`~/docs/devices/tailscale.md`、credentials 工具说明、`skill-creator/bin/scaffold-connector-skill` 和 `dynamic_credentials.py`。这些是它提供的路径，不是本轮 Codex 已读取的本地文件。

## 已纠正的判断

ChunLACK 是用户的自主私有协作与编排项目，不是 Raft 服务器；Slack 和 Raft 仅为交互设计参考。

X-Pilot、领取任务和租约属于 ChunLACK 自有业务协议。它们没有出现在 Muse 文档里，并不构成不兼容证据；要核对的是平台是否支持发送对应的通用 HTTP 方法、头和内容，以及如何运行整个执行流程。

老镇建议需要公网可达域名或自有网络方案，但当前项目仍要求不开放公网入口。域名是主机标识，不必然意味着公网服务；不能把这个建议变成对公开服务的授权。

## 下一阶段的安全门槛

1. 取得最小的内部调用接口和代理组合依据，避免仅凭 HTTP 库能力推断平台权限。
2. 在隔离的本地试点验证 skill 与 CLI 的通用业务协议，不读取真实 vault，不模拟“真实 Muse 已执行”。
3. 单独验证安全凭据注入、主机白名单、TLS 和官方私网代理能否同时成立。不得关闭 TLS 校验或把密钥复制进命令。
4. 组合链路明确后，再由用户批准私网配置和单次实际网络验证；仍不开放 VPS 公网端口。
5. 真实验收必须具备老镇自身浏览器活动、匹配截图和 ChunLACK 任务结果。终端 worker、HTTP 2xx 或本地合成图片不算通过。

本轮没有修改运行代码或重新运行测试。上一轮本地模拟测试通过不能替代上述门槛。本地留存的回复截图不提交到 GitHub，也不上传给第三方。
