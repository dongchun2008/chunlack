# 迁移后多人协作和恢复业务验收

## 本轮覆盖的真实流程

`tests/migrated-runtime-business.test.cjs` 使用独立临时目录和随机回环端口，执行旧 SQLite 数据准备、在线 WAL 一致快照、经确认的迁移、迁移独立复验、恢复副本准备、代码打包和真实应用启动。不是只检查表结构，也不替换服务端业务处理器。

一个实际场景包含三位测试用户与两个工作区：Alice 是研究工作区负责人，Bob 是其中成员和另一开发工作区负责人，Carol 是开发工作区只读用户。

- 通过真实 `/auth/login` 登录并读取工作区列表，验证伪造身份和权限不能访问未授权工作区。
- 在两个工作区同时保持真实 WebSocket 会话，读入迁移历史并写入各自消息，验证消息和模型上下文不跨工作区。
- 验证只读用户不能写入聊天或删除 Agent，负责人缺少 CSRF 也不能执行变更。
- 通过实际 `/ground` 完成两个 Agent 的一轮响应，各自走不同供应商路由，核对主回答请求、实际回复及原始来源上下文。
- 关闭并重启实际打包服务，重新登录，验证两边持久消息仍隔离，退出登录会撤销对应连接。
- 校验研究来源 URL、缺证标志仍保留；在独立恢复副本上启动当前打包程序的私有旧兼容模式，验证旧历史可以读取、未知旧表仍保留。
- 最后比对原库、原 WAL 和原配置的哈希，验证测试全过程没有修改它们。

## 两项实际问题的最小修正

旧 Memory 的召回曾假设所有记录都有 `trajectory` 或 `candidate` 文本。只有 URL 的记录或畸形条目会导致调用模型前出现 TypeError。现在召回只使用有效的原文本，忽略不适用条目的召回用途，但不改写、删除其存储记录，不把 URL 或未知值补造成叙述事实；有效 Embedding 的排序仍保留。

私有旧兼容模式曾将每个频道的启动消息初始化为空，导致 SQLite 历史虽存在却不在 WebSocket 历史中。现在使用已有的 `dbGetMessages` 初始化历史。该分支仍只在非多用户模式下执行，不改变公网多用户权限和跨工作区访问限制。

`tests/private-memory-legacy.test.cjs` 有四项独立回归：仅 URL 记录、畸形池与非文本记录、无效 Embedding 和评分、有效原始 Embedding 排序。修正前前三项真实失败；修正后全部通过。

## 试验条件，不能冒充的范围

- 认证采用顺序登录，然后三个会话并存。现有认证准入限制一次只进行一个密码校验，同时登录突发可能返回 429；本轮没有降低认证限制或证明三路密码校验并发。
- Agent 一轮响应按两个 Agent 各自的实际主回答计数，不以 HTTP 请求数、跟进提问或其他消息冒充完整一轮。触发前等待原有 2200 ms 响应冷却，测试不禁用这一限制。
- 模拟本地模型使用回环 HTTP，模拟云模型使用回环 HTTPS、临时测试证书和仅传入测试子进程的额外 CA。云模型使用虚构环境密钥；不关闭 TLS 证书校验，不调用真实云供应商，不依赖 Open WebUI。
- 本试点通过配置关闭 Musing 和 Triangulation 的多候选生成以控制资源；不删除这些能力，也不把低资源试点结果等同于其完整负载上限。
- 应用 HTTP/WebSocket 是隔离回环通道，手动传送安全 Cookie 验证服务行为；不是浏览器公网 HTTPS 交付验收。Caddy/TLS 的独立测试不能自动补足公网 DNS、证书和生产发布证据。
- 恢复启动使用当前打包版本的旧兼容模式，不是独立固定的历史发行版。复验恢复副本后应用会合法写入该测试副本；原快照和原数据库保持不变。数据工具的 `restoreReady` 与 `applicationConsistency` 标志不会被本次试验自动提升。
- 两 Agent 整轮成功不等同于五 Agent 持续压力验收，更不证明 Muse 老镇或 dots 玄玑自身电脑已经接入。

## 本地复验命令

```powershell
node --test --test-concurrency=1 tests/private-memory-legacy.test.cjs tests/migrated-runtime-business.test.cjs
```

测试需要项目已安装的依赖、Python 和 OpenSSL。Windows 使用现有 Git for Windows 的 OpenSSL，Linux 使用系统已有 `openssl`，不自动安装全局软件。测试只生成虚构账户和模型密钥，禁止将真实凭据填入测试文件。
