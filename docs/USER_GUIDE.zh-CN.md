## 一、先开始使用

1. 在 Windows、Mac 或其他设备的浏览器打开正式入口。
2. 点击“使用统一身份登录（Pocket ID）”，再点击继续按钮。
3. 本人完成通行密钥或 Windows Hello；不要把密码、验证码、私钥或令牌发给 Agent。
4. 核对顶部工作区名称、登录账号和角色。本次已验收的对应关系是工作区 `ChunLACK`、平台账号 `chunlack-owner`、角色“所有者”。
5. 等待底部显示 `CONNECTED`，再在 `general` 频道给现有 Agent 发一条短消息。

可先发送下面这条非敏感、仅讨论的消息：

```text
@1Cat 验收助手 请用三句话说明如何整理个人资料。
区分事实、建议和未知事项。本轮只讨论，不调用工具、不委派任务、不执行命令。
```

完整填写 Agent 名称，包括名称中的空格。“发起协作”会调用当前频道的 Agent，可能增加模型调用，不是设置按钮；不要连续点击重试。

当前已经配置的供应商是 `onecat-direct`，模型是 `qwen38-27b-nvfp4`。这不是要求你再安装一套模型。

### Pocket ID 提示超时，但似乎已经登录

Pocket ID 自身登录成功，不一定表示 ChunLACK 工作区会话已经建立。

- 返回正式入口，通过正常的“使用统一身份登录”流程继续。
- 以实际进入正确工作区、显示账号与角色作为平台登录依据；`CONNECTED` 另外表示网页实时连接已建立。
- 本次已观察到 Pocket ID 登录后，继续 ChunLACK 单点登录即可进入工作区；超时提示的具体根因尚未确认。
- 如果仍显示未授权或反复超时，保留时间和脱敏截图交给管理员，不要反复提交旧回调地址。
- 不跨浏览器复制登录回调，不重放授权码，不修改密钥、放宽 Cookie／证书校验或延长会话来绕过问题。
- 出现此前未批准的权限范围时先停止，由本人确认。

## 二、平台、设备、模型与 Agent

```text
Windows / Mac 浏览器
        |
        | HTTPS + 已授权真人会话
        v
VPS：ChunLACK 工作区、协作编排、权限与记录
        |
        | 既有私有网络
        v
现有直接推理路由 -> 1Cat 模型
```

VPS 不负责在本机加载大模型。当前链路不依赖 Open WebUI，也没有为模型新开公网端口。

| 概念 | 含义 |
|---|---|
| 设备 | Windows、Mac、DGX Spark 或其他计算机，是运行环境 |
| 模型服务 | 接收推理请求并生成输出，不等于能操作电脑的 Agent |
| ChunLACK 内部 Agent | 使用已配置模型与获准工具完成分工 |
| 外部 Agent | Muse 老镇、dots 玄玑等产品自身的执行者，需单独接入并验收 |
| 连接器／worker | 传递或执行已授权任务的程序；运行它不等于已经触发外部产品自身的 Agent |

同一台设备可以提供模型服务，也可以运行多个 Agent。接入模型 API 不会自动授予 ChunLACK 操作该设备文件、桌面或 shell 的权限。

## 三、认识界面

| 入口 | 用途与边界 |
|---|---|
| 当前工作区 | 切换已有成员资格的工作区，不是切换模型 |
| 成员 | 管理真人成员与其角色；不要通过提示词授予权限 |
| 节点 | 管理执行节点；显示节点不代表真实任务已验收 |
| 任务 | 查看执行状态；HTTP 收到请求不等于任务完成 |
| Agent 授权 | 管理外部执行者的受限授权；不是日常登录入口 |
| 频道导航按钮 | 展开左侧频道和 Agent 列表 |
| 添加 Agent | 打开页内表单，选择已经配置并获准使用的供应商和模型 |
| 三张引导卡片 | 填入草稿，仍需本人决定是否发送 |
| 工作台 | 项目文件、运行图表等入口，不是本机资源管理器 |
| 明暗按钮 | 仅改变显示主题 |
| CONNECTED | 网页实时连接成功，不单独证明模型、工具或外部节点可用 |

2026-10-19 曾在生产页面打开并取消“添加 Agent”表单，没有创建新 Agent或修改配置；这不是本次发布后的新页面验收。

## 四、添加和安排工作 Agent

当前已有 `1Cat 验收助手`；初次使用不必立即增加成员。确需创建时：

1. 展开频道导航，点击“添加 Agent”。
2. 填写名称、模型供应商、模型、系统提示词、参与频道及可选的限定频道。
3. 当前已配置供应商可选择 `onecat-direct`，模型选择 `qwen38-27b-nvfp4`。等待模型加载完成；失败时先排查，不重复提交。
4. 初次将参与频道明确改为 `general`。表单默认值可能包含 `general,siphon,code`。
5. 确认分工和作用域后再创建；仅查看时点击“取消”。

可按任务配置“方案员”“审查员”“检索员”“核验员”等名称和提示词。它们是任务分工，不是权限角色，也不要求每个分工使用不同模型。

```text
你是审查员。检查方案中的遗漏、风险和缺失证据。
区分已确认事实、推断与待核实事项，不编造来源。
本轮只提出建议，不执行命令、不修改文件、不委派任务。
回答尽量简短。
```

提示词不能替代服务器权限检查。不要随意删除或放宽 Moderator 的配置。

### 单 Agent 与多 Agent

- 指定一位成员时使用完整的 `@Agent名称`，并确认其属于当前工作区和频道。
- 明确需要多人讨论时再使用“发起协作”或相应协作流程。
- 五个逻辑 Agent 共用一个模型，不等于五台设备或五个同时推理的请求。
- 普通对话已调整为默认不自动追加反思或主动追问；显式选择的协作功能可能产生额外调用。
- 当前真实生产证据是一位 Agent 的单轮回复，不是五 Agent 持续容量承诺。
- 对于敏感材料，应核对所有可能参与的模型与执行者，不要仅靠名称或 `localOnly` 标签判断数据流向。

## 五、多人和工作区

一个私有平台可以管理多个工作区，同一工作区也可以有多个真人用户。每位真人使用自己的身份，不共享所有者会话。

- Pocket ID 身份认证与 ChunLACK 工作区成员资格是两件事。
- 不能因为能登录 Pocket ID，就推断有权访问任意工作区。
- 通过成员管理按实际职责分配角色；日常使用不必都给所有者权限。
- Agent 的任务分工与真人／节点的访问权限分开管理。
- 工作区、频道和任务用于组织工作；换一个研究主题通常不需要新建整套平台。
- 切换工作区后重新核对成员、模型授权和任务范围，不假定它们自动共享。

## 六、模型、工具和资料

2026-10-19 的配置快照：直接推理路由走既有私有网络，模型显式指定为 `qwen38-27b-nvfp4`，请求超时 30 秒、输出上限 512 token、没有配置回退模型。本次发布未调整模型配置，也未重新调用真实模型；这些不是所有任务的固定能力保证。

模型层保留 Ollama 与供应商中立路由。增加 llama.cpp、DGX Spark 或云模型时，应分别确认 VPS 可达地址、准确模型 ID、凭据引用、工作区授权与真实调用。不要在 VPS 上直接下载大模型，也不要复用 Open WebUI 的地址或密钥代替直接模型服务。

- 密钥只保存在获准的私有配置中，不进入聊天、附件、提示词或 Git。
- 本地电脑操作需另外完成受控执行节点的授权与真实验收；浏览器登录不能替代它。
- 不使用 `/bash`、数据重置或自动循环来测试基本连接。
- 研究结果需保留原始来源链接，缺证明确标注。模型生成的引用仍须核对，不能当作已检索证据。
- 附件入口不是完整知识库入库，不保证整份长文件都进入上下文；长资料应先选取相关、脱敏片段。
- `/help` 可以查看页面现有帮助，但命令出现在帮助中不代表该账号已获权限或该能力已经验收。
- `/stop` 不应被当作整个系统的全局急停承诺；已有请求和独立流程须核对实际状态。

接入验收必须包含：平台唯一任务与校验码、外部 Agent 实际领任务、其自身电脑的动作记录、截图或其他证据、ChunLACK 保存的结果及收件确认。只有 HTTP 2xx、模型回复或自建 worker 执行，不能作为这些产品的原生能力接入证明。

有关实现和管理员流程可参阅[Agent 授权管理说明](AGENT_GRANT_ADMIN_GUIDE.zh-CN.md)；执行会创建权限的步骤前仍须确认实际账号、工作区、能力和期限。

## 八、记录、性能与安全使用

本轮已核对真实生产回复写入数据库，刷新页面后仍可见。此前 Windows 隔离试验另行验证过隔离运行时重启后的回复 ID 和内容哈希；这不等于所有未完成任务都能在生产重启后自动续跑。

已有容量协调与预算机制，但不能把历史模拟压测、五个 WebSocket 连接或单轮模型成功当作五节点全天候容量保证。先保持任务简短，避免同时启动多个长期循环。

重要成果另行保存到项目文档。页面为空、超时或断线时不要重置数据、删除数据库或删除遗留写锁。

## 九、管理员维护：先分清新旧服务

日常用户不需要 SSH。以下只读检查仅供已获准的管理员在 VPS 执行：

```bash
systemctl show chunlack-public.service chunlack-https.service -p ActiveState -p MainPID -p NRestarts
curl --fail --max-time 10 https://lack.chunclaw.top/health
systemctl show chunlack.service tailscaled.service -p ActiveState -p MainPID -p NRestarts
```

健康接口返回 200 仅证明该检查通过，不替代登录、模型、节点或 Relay 真实流量验收。

| 服务或路径 | 含义 |
|---|---|
| `chunlack-public.service` | 当前公网 ChunLACK 应用 |
| `chunlack-https.service` | 当前 HTTPS 入口 |
| `chunlack.service` | 保留的旧 LACK，不要用它的重启命令维护新应用 |
| `tailscaled.service` | 现有 Tailscale／Relay 服务，不因普通应用配置而重启或改动 |
| `/opt/chunlack-public/current` | 当前公网应用代码 |
| `/var/lib/chunlack-public/config/lack.config.json` | 当前公网应用配置 |
| `/etc/chunlack-public/runtime.env` | 私有运行环境文件，不打印或提交 |
| `/var/backups/chunlack-release-44af1d844a81` | 当前发布的一致性备份，已核对 552 个文件及 3 个数据库结构；不是异地备份 |

不得把旧版 SSH 隧道的 `127.0.0.1:3721` 当成当前公网工作区入口。遗留隧道仅是另一个访问路径，不应用于证明新系统已登录。

升级或回滚仍需维护窗口、资源检查和一致性备份。既定受控发布预算是 55 秒前向、120 秒总恢复窗口；不要绕过失败停止条件。保留旧版本，不以回滚代码为理由覆盖较新的业务数据，不删除遗留写锁，不运行上游一键安装器覆盖现有部署。

## 十、常见问题

| 现象 | 建议检查 |
|---|---|
| Pocket ID 已登录，但 ChunLACK 仍显示登录页 | 从正式入口重新发起正常 SSO，核对是否建立工作区会话 |
| 页面打不开 | 正式域名、网络、HTTPS 入口与健康检查，不先开放 3721 |
| CONNECTED 但 Agent 不回复 | 当前工作区、完整 Agent 名称、频道和模型错误；不要重复发起协作 |
| 添加 Agent 时模型未加载 | 供应商配置、授权和加载状态；不要重复创建或填写密钥 |
| 文件树加载失败 | 当前会话与目录作用域；不放宽目录权限或重置数据 |
| 历史暂时为空 | 等待实时连接和历史加载，再核对数据库；不立即判定数据丢失 |
| 无法操作本地电脑 | 核对是否已经完成该设备的执行连接器接入，而不是仅接了模型 |
| 外部 MCP 返回未授权 | 当前可能尚未授予客户端与工作区权限，不改成匿名访问 |
| 回复慢、重复或费用增加 | 成员数量、协作模式、循环、上下文与输出预算；先停止重复提交 |
