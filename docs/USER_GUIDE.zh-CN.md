# LACK 中文使用手册

适用版本：LACK v4.2.2 Hybrid，牛油果主题，应用发布版本 `e188eae`。  
编写日期：2026-09-14。本文面向当前私有 VPS 部署，不适用于上游桌面一键安装器。

> 最短使用路径：建立 SSH 隧道 → 打开网页 → 配置一个真实模型服务 → 添加两个 Agent → 在同一频道发送一项简单任务。
>
> 当前部署记录显示：网页服务已上线，真实模型尚未接入，只有内置 Moderator。本文不会自动完成模型配置。后续状态如有变化，以实际配置和调用结果为准。

## 一、LACK 能帮你做什么

LACK 是一个多 Agent 聊天协作工作台。你可以给不同 Agent 分配角色、提示词和模型，让它们围绕同一任务讨论、提出方案、审查结果。

例如：

```text
你提出一个目标
    ↓
LACK 频道保存本轮对话
    ↓
方案 Agent 提出步骤
审查 Agent 指出风险
其他 Agent 补充观点
    ↓
你决定是否继续、修改或采用结果
```

这是一种工作组织方式，不代表当前程序会严格按照你写下的角色顺序进行调度，也不代表所有 Agent 会同时推理。

| 可以使用的能力 | 不应直接理解为 |
|---|---|
| 多个 Agent 在频道中回复 | 自动运行完整的项目管理系统 |
| 每个 Agent 选择不同供应商和模型 | 已经接通这些模型服务 |
| 规划、审查和线程讨论 | 模型结论已经过事实验证 |
| VPS 中的受限文件和工具能力 | 可以任意操作你的 Windows 或 Mac |
| 数据持久化 | 重启后所有历史都能正确显示 |

Codex/OpenClaw 本地节点连接器目前未部署。连接一个模型 API 也不会自动赋予 LACK 本地电脑操作权限。

## 二、如何打开网页

### 2.1 为什么不能直接访问 VPS 的公网端口

LACK 程序和数据都在 VPS 上。当前服务只监听 VPS 内部的 `127.0.0.1:3721`，没有直接向公网开放，也没有配置完整的公网登录与权限系统。

你电脑上的 `127.0.0.1:13721` 是 SSH 隧道入口，不是把 LACK 安装到了本机。

```text
本机浏览器：127.0.0.1:13721
    ↓ SSH 加密隧道
VPS 内部：127.0.0.1:3721
    ↓
VPS 上运行的 LACK
```

### 2.2 Windows 和 Mac 的连接方法

Windows 打开 PowerShell，Mac 打开终端。将下方 `VPS_HOST` 替换为你的 VPS 地址，然后执行：

```bash
ssh -N -L 13721:127.0.0.1:3721 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -p 22 root@VPS_HOST
```

1. 首次连接如出现主机指纹提示，先与服务器的可信记录核对。
2. 按提示输入 VPS 密码，或使用管理员已经配置的 SSH 密钥。
3. 密码输入时不显示字符是正常现象。
4. 成功后通常没有新输出，保持终端窗口开启。
5. 在执行命令的同一台电脑打开 [LACK 页面](http://127.0.0.1:13721/)。

如果已由 Codex 建立隧道，可以直接打开页面，无需再开一条同端口隧道。隧道断开后需要重新连接。

日常使用建议在自己的 PowerShell 或终端中保持这条命令运行，不要只依赖临时的助手连接。关闭终端、电脑休眠或网络中断可能导致隧道失效；浏览器仍可能显示已经加载的界面，但新的文件树和聊天请求会失败。上述保活参数用于探测连接，不会在进程退出后自动重连。

每台 Windows/Mac 都要建立自己的隧道。手机不能使用另一台电脑的 `127.0.0.1`；手机直连需要另行配置受控的私有访问入口。

### 2.3 端口被占用怎么办

先直接打开页面，原隧道可能仍在运行。如果确实有其他程序占用，可换一个本机端口：

```bash
ssh -N -L 13724:127.0.0.1:3721 -o ExitOnForwardFailure=yes -p 22 root@VPS_HOST
```

这时浏览器打开 `http://127.0.0.1:13724/`。VPS 内部仍使用 `3721`，不需要修改服务配置或防火墙。

## 四、先接入模型，再创建 Agent

### 4.1 准备哪些信息

接入模型需要以下信息，可交给管理员配置：

| 信息 | 示例或说明 |
|---|---|
| 服务类型 | Ollama，或 OpenAI-compatible API |
| API 基础地址 | 以服务商文档为准，通常包含 `/v1` |
| 模型 ID | 接口使用的准确标识，不只是模型的展示名称 |
| 是否需要密钥 | 云端通常需要；私有本地服务也可能需要 |
| VPS 是否能够访问 | 本机可访问不等于 VPS 可访问 |

**不要把 API Key、VPS 密码或 SSH 私钥放进聊天、Agent 提示词、附件或 GitHub。**

供应商配置在服务器上完成。Agent 窗口的 Provider 下拉框用于选择已经配置的供应商，不是填写密钥的地方。

### 4.2 如果调用 Windows/Mac 上的本地模型

模型服务的地址必须从 VPS 可达，可以使用已经授权的 Tailscale 私有连接。

```text
VPS 上的 LACK → 本地机器的私有网络地址 → 本地模型服务
```

- 不要把 VPS 的 `localhost` 当成本地 Windows/Mac。
- 不要假定家庭局域网地址能从 VPS 直接访问。
- 本地电脑要保持在线，模型服务要运行，并允许来自已授权节点的请求。
- 不要为了方便把无鉴权模型接口暴露到公网。
- Tailscale Relay 的存在不等于所有节点访问权限和路由都已配置完成。

### 4.3 如何判断模型真正接通

看到供应商名称或模型列表只代表发现/配置阶段有结果，有些模型列表来自静态配置。

实际验收应当是：在测试频道发送一个短问题，得到正常回复，再由管理员核对路由日志。首次建议只接一个模型、一个或两个 Agent，不要同时接入全部供应商。

## 五、创建你的第一组 Agent

建议先创建两个，而不是一开始就启用五个。

### 5.1 创建方案员

点击左侧“添加 Agent”。当前创建流程会依次弹出以下输入框：

| 输入项 | 建议填写 |
|---|---|
| `Provider` | 管理员已配置的准确供应商 ID |
| `Agent name` | `方案员` |
| `Model` | 可用的准确模型 ID |
| `System prompt` | 使用下方提示词 |
| `Channels (comma)` | `general` |
| `Strict channel` | 初次可留空；希望限制在一个频道时填 `general` |

```text
你是方案员。根据用户目标提出清晰、可执行的方案。
明确区分事实、假设和待确认事项。
输出建议步骤、主要依赖和验收标准。
默认只讨论，不主动执行工具或修改文件；需要执行时先说明原因并请求确认。
每次回答尽量控制在300字以内。
```

注意：创建流程的默认频道可能是 `general,siphon,code`。初次使用请主动改成 `general`，避免 Agent 在不需要的频道参与。

### 5.2 创建审查员

重复创建流程，名称填 `审查员`，频道也填 `general`。可以使用同一个模型，也可以选择另一个已配置供应商。

```text
你是审查员。检查用户目标和已有方案中的遗漏、风险、依赖及未经证实的判断。
提出具体改进建议，不为了反对而反对。
信息不足时说明缺少什么，不编造事实或执行结果。
默认只讨论，不主动执行工具或修改文件；需要执行时先请求确认。
每次回答尽量控制在300字以内。
```

提示词中的限制不能替代服务器权限控制。涉及执行能力时，仍必须依靠工具策略、隔离和明确授权。

### 5.3 修改已有 Agent

点击 Agent 名称打开详情，点击 `Edit`，可调整名称、Provider、Model、System Prompt、Channels 等，完成后点击 `Save`。

供应商显示 `unconfigured` 时，先处理服务器配置，不要反复切换模型尝试绕过。不要随意删除内置 Moderator。

## 六、发送第一项协作任务

确认两个 Agent 都加入 `general`，在该频道发送：

```text
请讨论如何整理一个个人资料库。

目标：能够按主题查找资料，并区分原文、摘要和个人笔记。
限制：先用现有设备，不购买新服务。

方案员：提出一个简单、可执行的流程。
审查员：指出遗漏、风险和需要进一步确认的地方。

本轮仅讨论，不执行命令、不创建或修改文件。
每位成员不超过300字。没有资料依据的结论要标注为假设。
```

等待这一轮成员回复完毕，再发送追问。先用简单任务确认流程，不要立刻启动长期研究或自动执行。

### 6.1 如何继续讨论

```text
请结合刚才的意见，把方案收敛为3个步骤。
每一步写明输入、输出和完成标准。
仍然只讨论，不执行任何操作。
```

点击某条消息的回复入口，可以进入线程继续围绕该条内容讨论。在手机布局下，线程面板可通过关闭按钮返回主频道。

### 6.2 频道和并发的区别

**当前实现中，普通频道消息会触发符合条件的频道成员参与。`@某个Agent` 不是可靠的“只调用此人”开关。**

一个任务可以由五个 Agent 协作，但这不等于五个独立任务，也不等于同时有五个模型请求。一般聊天链路会依次等待部分响应；反思和后台处理也可能增加额外调用。

希望只由一位 Agent 回答时，应先由管理员安排只包含该工作 Agent 的独立频道或相应作用域，不要仅依靠 `@`。

敏感任务不能与云端 Agent 混在同一个共享频道，然后仅靠某一个 Agent 的 `localOnly` 保证全部内容留在本地。

## 七、常用命令与任务模板

### 7.1 初期只需掌握这些命令

| 命令 | 用途 | 注意事项 |
|---|---|---|
| `/help` | 查看实际命令帮助 | 可以先从这里了解功能 |
| `/list` | 列出 Agent | 用于核对成员 |
| `/ground` | 触发频道成员回应 | 与“发起协作”相关，会增加模型调用 |
| `/plan 目标` | 启动目标规划 | 属于进阶功能，可能持续调用模型或涉及动作流程 |
| `/stop` | 请求停止当前频道的常规循环 | 不是全局急停，不保证取消已经发出的请求或所有独立流程 |
| `/errorlog` | 查看错误记录 | 分享日志前先检查是否含敏感信息 |
| `/memory Agent_ID` | 查看指定 Agent 的记忆信息 | 使用实际 ID；当前未启用向量嵌入，不能当作完整 RAG |

`/research`、`/ralph`、`/reconcile`、`/cicd` 等功能可能带来重复调用、持续循环、联网或文件操作。普通讨论跑通后，再按具体目标单独配置和验证。

不要用 `/bash` 测试服务器权限。当前部署默认禁用 shell；Moderator 的存在也不等于获得不受限的系统访问。

## 八、附件、记忆和历史记录

### 8.1 文本附件的限制

当前附件入口支持若干文本格式，例如 `.txt`、`.md`、`.json`、`.csv` 和部分代码文件。界面限制为 512 KiB，但发送时只截取约前 1500 个字符加入消息。

- 不是整份长文档解析，也不是知识库入库。
- 长资料应先提取相关片段，并明确告诉 Agent 哪些内容未提供。
- 中文或其他非 ASCII 附件应先检查消息内容是否正常显示。
- 不要上传密码、密钥、完整私有配置或未经脱敏的敏感资料。

### 8.2 记忆和上下文不是无限的

当前一般聊天上下文只保留有限条近期相关消息，不能假定所有历史都送给模型。重要约束建议在新任务中重新简要列出。

部署时关闭了向量嵌入及部分增强功能。记忆池不等于已经建成可检索全部文档的知识库。

### 8.3 已知历史显示问题

当前仍存在服务重启后频道历史未完整加载到界面的已知问题。数据库有数据与网页能显示历史，是两件不同的事。

重要结论应另行保存到你自己的文档或项目记录中。不要因为页面为空就点击重置，也不要自行删除数据库。

## 九、这台小 VPS 怎么用更稳妥

根据已完成的模拟压力测试，建议先采用：

| 项目 | 建议 |
|---|---|
| 初次 Agent 数量 | 1～2 个，流程稳定后再扩展 |
| 工作 Agent 数量 | 可试用 5 个，模型推理放在外部服务 |
| 日常并发独立任务 | 先 1 个，熟悉后最多按 2 个组织 |
| 保守的已测并发档位 | 3 个独立任务，不是已强制生效的系统限制 |
| 单轮输出 | 尽量精简，避免所有成员重复长文 |
| 自动循环和进阶推理 | 按需启用，避免同时开启多个长期循环 |

目前没有实现强制全局排队限流，不能依靠系统自动替你把所有工作约束在上述范围内。压测使用模拟模型，不代表真实模型速度、账单或全天候稳定性保证。

一次任务还可能触发反思、评价等额外请求。不要把“五次 Agent 回复”直接等同于“五次付费模型调用”。

## 十、常见问题排查

| 现象 | 先检查什么 | 不要做什么 |
|---|---|---|
| 浏览器打不开页面 | SSH 隧道是否连接；本机端口是否一致 | 不要直接开放公网 `3721` |
| `Address already in use` | 原隧道是否仍在运行；必要时换本机端口 | 不要随意结束不认识的进程 |
| 页面显示 `DISCONNECTED` | SSH 连接和 LACK 服务状态 | 不要先清数据库 |
| 项目文件显示 `Failed to load tree.` | 先确认本机 SSH 隧道仍在，再由管理员检查 `/api/tree?root=thread_repos`；正常空目录返回 `[]`，当前界面会显示空白列表 | 不要因空列表重置数据或放宽目录权限 |
| `CONNECTED` 但 Agent 不回复 | 模型是否真实接通、成员是否加入频道、错误日志 | 不要把连接状态当成模型健康状态 |
| 没有可用模型 | Provider 地址、密钥、模型 ID 与发现接口 | 不要在提示词里填写 API Key |
| 添加 Agent 失败 | 是否准确选择已配置 Provider，模型列表是否有效 | 不要把界面创建流程当成供应商安装器 |
| 多个 Agent 都回复 | 它们是否都加入了当前频道 | 不要假设 `@` 会自动排除其他成员 |
| 回复慢或费用增加 | 成员数量、上下文、输出长度、循环和反思调用 | 不要连续重复点击“发起协作” |
| 重启后聊天区为空 | 已知历史加载限制；请管理员核对持久化数据 | 不要点击 CRON 重置 |
| 无法操作 Windows/Mac | 当前未部署本地执行连接器 | 不要给 LACK 挂载整台主机文件系统 |

## 十一、管理员附录：配置与维护

本节由熟悉服务器配置的人操作。普通使用者先完成前面章节即可。

### 11.1 当前 systemd 部署路径

| VPS 路径 | 用途 |
|---|---|
| `/opt/chunlack/current` | 当前应用版本指针 |
| `/opt/chunlack/releases/` | 保留的应用版本 |
| `/var/lib/chunlack/config/lack.config.json` | 实际运行配置 |
| `/etc/chunlack/provider.env` | 私有供应商密钥环境文件 |
| `/var/lib/chunlack/db/lack.db` | SQLite 数据库 |

### 11.2 添加云端 OpenAI-compatible 供应商

先备份现有配置。以下内容是**字段示例，不是可直接覆盖现有文件的完整配置**。将供应商对象追加到现有 `llmCloudProviders` 数组，保留已有成员和其他配置。

```json
{
  "id": "cloud-main",
  "type": "openai-compatible",
  "baseUrl": "https://model-api.example.com/v1",
  "apiKeyEnv": "LACK_CLOUD_MAIN_API_KEY",
  "models": ["YOUR_MODEL_ID"],
  "fallbackModels": [],
  "maxTokens": 2048
}
```

`example.com` 地址和模型 ID 是占位示例，必须替换。通过服务器上的安全编辑器在私有环境文件中设置对应变量：

```dotenv
LACK_CLOUD_MAIN_API_KEY=YOUR_PRIVATE_API_KEY
```

这只是格式示意，真实密钥不得写入仓库。保持环境文件由 root 持有、权限 `600`，避免输出其内容到日志或终端共享记录。

### 11.3 添加私有本地 OpenAI-compatible 供应商

以下对象追加到 `llmProviders` 数组。仅在服务确实无需鉴权、且访问范围已受控时，才能使用 `requiresApiKey: false`。

```json
{
  "id": "local-main",
  "type": "openai-compatible",
  "baseUrl": "http://PRIVATE_MODEL_HOST:PORT/v1",
  "local": true,
  "requiresApiKey": false,
  "models": ["YOUR_LOCAL_MODEL_ID"]
}
```

如果本地服务需要密钥，应保留鉴权要求并使用 `apiKeyEnv` 指向独立密钥。`local: true` 是路由策略标签，不会自动建立网络连接、加密通信或限制对外访问。

原有 Ollama 支持保留。使用原生 Ollama 路径时，应由管理员配置实际可达地址；本手册不会要求在这台小 VPS 上下载或运行大模型。

配置完成后，安排仅重启 LACK 的维护窗口，再刷新页面、选择供应商，并进行真实调用验证。不要重启 Tailscale Relay，也不要整机重启来应用普通模型配置。

### 11.4 常用只读检查

以下命令在 VPS 的 SSH 终端中运行：

```bash
systemctl status chunlack --no-pager
curl --fail http://127.0.0.1:3721/health
journalctl -u chunlack --since '10 minutes ago' --no-pager
```

分享日志前先脱敏。不要为了排障打印私有密钥环境文件。

确需应用配置时，仅在已备份并确认可短暂停机后使用：

```bash
systemctl restart chunlack
```

应用重启可能短暂断开网页连接，并触发已知历史显示限制。持续运行的任务应先处理完毕。

### 11.5 升级、回滚和危险操作

- 使用独立版本目录升级，保留旧版本和数据备份。
- 不要在 VPS 上直接运行上游 `python lack.py` 一键安装器覆盖现有部署。
- 不要为了更换界面或回滚代码而覆盖较新的业务数据。
- 不要点击 CRON 重置来修复页面样式、模型超时或 SSH 问题。
- 本地备份应另行安排受控的异地副本；不要上传含密钥的数据包到公共仓库。

- [ ] 至少一个模型服务已完成真实调用验证。
- [ ] 已添加一个或两个工作 Agent，并核对它们的频道。
- [ ] 已用一项简单、非敏感、仅讨论的任务跑通流程。
- [ ] 知道附件和上下文不是无限长度。
- [ ] 知道当前没有本地电脑执行连接器和强制全局限流。
- [ ] 不使用 CRON 重置，不把密钥放进聊天。
