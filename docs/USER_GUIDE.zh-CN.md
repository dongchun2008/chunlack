## 一、先开始使用

1. 在 Windows、Mac 或其他设备的浏览器打开日常入口。
2. 点击“使用统一身份登录（Pocket ID）”，再点击继续按钮。
3. 本人完成所需的通行密钥或 Windows Hello；不要把密码、验证码、私钥或令牌发给 Agent。沿用既有身份会话不等于重新验证了一次通行密钥。
4. 核对顶部工作区名称、登录账号和角色。历史验收对应工作区 `ChunLACK` 与既有所有者账号；原手册记录的平台账号为 `chunlack-owner`、角色为“所有者”。2026-10-24 记录确认预期既有所有者账号和角色可见，但未公开原始账号标识。
5. 等待底部显示 `CONNECTED`，再按需要在 `general` 频道给现有 Agent 发一条短消息。连接指示不保证模型或执行节点可用。

可先发送下面这条非敏感、仅讨论的消息；发送会产生模型调用，本次文档修订没有发送它：

```text
@1Cat 验收助手 请用三句话说明如何整理个人资料。
区分事实、建议和未知事项。本轮只讨论，不调用工具、不委派任务、不执行命令。
```

完整填写 Agent 名称，包括名称中的空格。“发起协作”会调用当前频道的 Agent，可能增加模型调用，不是设置按钮；不要连续点击重试。

历史配置的供应商为 `onecat-direct`，模型为 `qwen38-27b-nvfp4`。这不是要求再安装一套模型，也不是本次对当前配置的确认。

## 二、平台、设备、模型与 Agent

```text
Windows / Mac 浏览器
        |
        | HTTPS + 已授权真人会话
        v
VPS：ChunLACK 工作区、协作编排、权限与记录
        |
        | 既有私有网络
        v
现有直接推理路由 -> 1Cat 模型
```

以上说明已有路线，不是当前网络状态探测。VPS 不负责在本机加载大模型。直接模型路线不依赖 Open WebUI，不增加 Open WebUI 集成，也不要求为模型新开公网端口。

| 概念 | 含义 |
|---|---|
| 设备 | Windows、Mac、DGX Spark 或其他计算机，是运行环境 |
| 模型服务 | 接收推理请求并生成输出，不等于能操作电脑的 Agent |
| ChunLACK 内部 Agent | 使用已配置模型与获准工具完成分工 |
| 外部 Agent | dots 玄玑、待核验的 Muse 苏婳等产品自身的执行者；Muse 老镇仅指历史对象 |
| 连接器／worker | 传递或执行已授权任务的程序；运行它不等于触发外部产品自身的 Agent |

同一台设备可以提供模型服务，也可以运行多个 Agent。接入模型 API 不会自动授予 ChunLACK 操作该设备文件、桌面或 shell 的权限。

## 四、添加和安排工作 Agent

历史配置中已有 `1Cat 验收助手`；初次使用不必立即增加成员。确需创建时：

1. 展开频道导航，点击“添加 Agent”。
2. 填写名称、模型供应商、模型、系统提示词、参与频道及可选的限定频道。
3. 若管理员确认历史直接路线仍获授权且可用，可选择 `onecat-direct` 和 `qwen38-27b-nvfp4`；其他获准供应商与模型也应通过中立配置选择。等待模型列表加载完成；失败时先排查，不重复提交。
4. 初次将参与频道明确改为 `general`。表单默认值可能包含 `general,siphon,code`。
5. 确认分工和作用域后再创建；仅查看时点击“取消”。

可按任务配置“方案员”“审查员”“检索员”“核验员”等名称和提示词。它们是任务分工，不是权限角色，也不要求每个分工使用不同模型。

```text
你是审查员。检查方案中的遗漏、风险和缺失证据。
区分已确认事实、推断与待核实事项，不编造来源。
本轮只提出建议，不执行命令、不修改文件、不委派任务。
回答尽量简短。
```

提示词不能替代服务器权限检查。不要随意删除或放宽 Moderator 的配置。

### 单 Agent 与多 Agent

- 指定一位成员时使用完整的 `@Agent名称`，并确认其属于当前工作区和频道。
- 明确需要多人讨论时再使用“发起协作”或相应协作流程。
- 五个逻辑 Agent 共用一个模型，不等于五台设备或五个同时推理请求。
- 原手册记载普通对话默认不自动追加反思或主动追问；显式选择的协作功能可能产生额外调用。本次未重新检查当前实现。
- 2026-10-19 正式工作区模型证据覆盖一位 Agent 的单轮回复，不是五 Agent 持续容量承诺；2026-10-24 登录验收没有新增推理证据。
- 敏感材料应核对所有可能参与的模型与执行者，不要仅靠名称或 `localOnly` 标签判断数据流向。

## 五、多人和工作区

一个私有平台可以管理多个工作区，同一工作区也可以有多个真人用户。每位真人使用自己的身份，不共享所有者会话。这是使用与权限原则，不代表多真人并行使用已经验收。

- Pocket ID 身份认证与 ChunLACK 工作区成员资格是两件事。
- 能登录 Pocket ID，不表示有权访问任意工作区。
- 通过成员管理按职责分配角色；日常使用不必都给所有者权限。
- Agent 任务分工与真人／节点访问权限分开管理。
- 工作区、频道和任务用于组织工作；换研究主题通常不需要新建整套平台。
- 切换工作区后重新核对成员、模型授权和任务范围，不假定自动共享。
- 拟议界面语言偏好属于真人用户与其浏览器，不因工作区或 Agent 设置而成为共享配置。

### 再次执行与苏婳接入的边界

接入验收必须包含：平台唯一任务与校验码、外部 Agent 实际领任务、其自身电脑动作记录、截图或其他证据、ChunLACK 保存的结果及收件确认、本人明确验收。HTTP 2xx、模型回复或自建 worker 执行不能替代这些证据。

再次试点须重新确认实际账号、工作区、节点、能力、范围和期限，不能复用已撤销的 `grantId`。连接发现可使用 `chunlack_connections_list`；上传的 `artifact_begin`、`artifact_chunk`、`artifact_finish` 和 `leaseId`、`attempt` 等字段以真实工具与任务为准，不猜造。`events.read`、`events.subscribe` 需单独审阅，不能从勾选 scope 推定 Events 已启用。本段只是流程说明，不授权新任务、授权或订阅。

苏婳应独立核实受支持连接器、认证、回调、工具可见性、唤醒与撤销路径，再在获准范围内验收。老镇历史节点、grant、审计、任务和附件保留原始身份，不重命名、不自动迁移权限，不把旧结果计为苏婳成绩。Muse Gadgets SDK／BLE 是另一条设备路线，不是云端电脑接入条件，不应安装到 VPS root 账户。

“需要重新认证”或 `insufficient_scope` 也可能来自本地业务授权过期／撤销；先核对绑定与授权状态，不循环登录或盲目扩大 scope。参阅[接入说明](MUSE_DOTS_INTEGRATION.zh-CN.md)、[Agent 授权管理说明](AGENT_GRANT_ADMIN_GUIDE.zh-CN.md)和[公开浏览协议](public-node-task-pilot.md)。接入说明中的老镇恢复步骤及更早私网／Open WebUI 历史段落不是苏婳当前方案；本文采用用户最新身份说明和两份较新验收记录，未修改历史文件。

## 十、常见问题

| 现象 | 建议检查 |
|---|---|
| Pocket ID 已登录，ChunLACK 仍是登录页 | 从日常入口重新正常 SSO，核对工作区会话；保留 `Session ID is missing` 等原始错误 |
| 页面打不开 | 日常域名、网络、HTTPS 与健康检查，不先开放 3721；历史验收不等于当前在线 |
| CONNECTED 但 Agent 不回复 | 工作区、完整 Agent 名称、频道与模型错误；不重复发起协作 |
| 添加 Agent 时模型未加载 | 供应商配置、授权与加载状态；不重复创建或填写密钥 |
| 文件树加载失败 | 当前会话与目录作用域；不放宽权限或重置数据 |
| 历史暂时为空 | 等待实时连接与历史加载，再核对数据库；不立即认定数据丢失 |
| 无法操作本地电脑 | 核对该设备执行连接器授权与真实验收，不仅是模型 API |
| 外部 MCP 未授权 | 核对客户端、账号、工作区授权及撤销／到期，不改匿名访问、不循环登录 |
| 玄玑曾成功，现在不接单 | 历史试点授权已撤销且未启用 Events；新任务另需有界授权，不是持续在线服务 |
| Muse 对象或名称不同 | 老镇历史且不再可用，苏婳待独立验收；不改名历史节点或继承旧 grant |
| 没有语言切换或英文界面 | 多语言 UI 本地开发、未发布；偏好拟按真人用户＋浏览器保存 |
| 切换语言后消息未翻译 | 界面语言不自动翻译消息、附件或证据，保留原始内容 |
| 回复慢、重复或费用增加 | 成员数量、协作模式、循环、上下文与输出预算；先停止重复提交 |
