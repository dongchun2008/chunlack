# 启动错误取证方案：先识别日志通道，不再盲目重跑

日期：2026-11-03。状态：仅本地方案和上游源码核对，未执行新增远端操作，未发布。

## 已确认的现场与缺口

前两次限定只读采集分别取得了管理器的 226/NAMESPACE 摘要，以及固定 boot、PID、精确进程生命周期查询的零条结果。冻结绑定对应的 53 个路径及父目录在主机视图中存在，未见符号链接。这些事实均不证明失败 namespace 内的挂载已成功，也不确定具体失败路径或 errno。

零条结果只描述实际执行过的查询，不表示其他通道没有日志。产品原生测试与生产交付门槛尚未因此通过。

## 新的上游源码依据

本次核对的是 systemd 的固定 v255 标签，不是已确认的 VPS 安装版本。发行版补丁、运行中管理器与磁盘客户端的版本差异仍未知。

- [execute.c](https://github.com/systemd/systemd/blob/v255/src/core/execute.c)：执行辅助程序的日志目标由管理器单独传入，不等同于业务程序的 stderr。
- [executor.c](https://github.com/systemd/systemd/blob/v255/src/core/executor.c)：辅助程序先完成日志初始化及参数解析，再允许日志 IPC、打开最终目标，随后执行配置反序列化和执行流程。不能只看到前面的禁止 IPC 就断言后续始终禁止 IPC。
- [exec-invoke.c](https://github.com/systemd/systemd/blob/v255/src/core/exec-invoke.c)：参考实现中，标准输入输出设置先于挂载 namespace 设置；挂载失败使用 systemd 自身日志函数报告错误及可用的错误路径。因此不能声称 namespace 错误必然写进已连接的 stderr。
- [manager.c](https://github.com/systemd/systemd/blob/v255/src/core/manager.c)：参考实现依据管理器目标及 journal 可用情况选择辅助程序日志目标。
- [log.c](https://github.com/systemd/systemd/blob/v255/src/basic/log.c)：日志实现包含 journal、内核日志和控制台路径；内核日志写入形式含消息文本中的发送进程标识。文本标识不等于 journal 的可信 `_PID` 字段。

推论：辅助程序日志路由不同，是之前两类查询未取得详细错误的一种可检验解释，不是已确认根因。上游参考实现也不能证明该 VPS 选择了内核日志、错误实际写入成功或记录仍然保留。

## 备选路线与选择

1. 重复旧 PID 查询：不选。没有新的选择条件依据，预计不能弥补日志通道未知的问题。
2. 直接新建同参数探针：暂缓。保持安全参数是必要条件，但没有可靠取证通道时可能重复得到同一个无细节结果。
3. 先核对版本及日志目标：推荐。新增远端预算另行批准后，仅只读取得运行中管理器版本、客户端版本和当前日志目标，先判断参考实现是否适用。现阶段不读取更多历史日志、不启动探针。

## 下一关键操作的精确提案，尚未执行

最多一次 SSH，远端最多 20 秒、外层最多 35 秒、无自动重试，不创建 Linux 单元。

- 用既有固定主机指纹及私有 SSH 传输，不暴露或改写凭据。
- 复用现有四服务、选定文件元数据和监听集合的前后保护基线，不扩大为全机业务数据读取。
- 只读调用 `/usr/bin/systemctl --version` 与 `/usr/bin/journalctl --version`，记录客户端版本。
- 通过固定 D-Bus 管理器对象的 `Version` 属性取得运行中管理器版本；不把客户端版本自动当作运行版本。
- 只读调用无参数的 `/usr/bin/systemctl log-target`，不附带目标值，不调用设置接口。
- 限制每条命令、输出及总截止时间；不支持、超时或版本不一致时明确记录未知并停止，不切换到全局日志、控制台或内核缓冲区读取。
- 本提案不追加 journal 查询、不读取凭据正文、不写远端文件、不启停服务，不改变 DNS、端口、授权或 Relay。

上述远端操作需要单独确认。批准前仅保留本地文档，不生成可自动运行的 SSH／单元启动入口。

## 后续决策门槛

版本或目标未知时，不批准以“设置 StandardError 就能捕获启动错误”为前提的新探针。先核对与实际版本对应的上游及发行版实现，不能套用固定 v255 的内部行为。

若后续证据明确指向 journal，才提出有上限且严格限于目标的读路径；若指向内核日志，必须另行设计 boot、精确时间、完整唯一单元名和消息进程标识的联合限定。该类文本匹配只是诊断候选，不是可信进程身份或权限依据，不直接触发修复。不得将固定 `_PID` 过滤机械用于所有日志传输。

如需全新探针，必须另行给出新目录、固定源码与摘要、一次性额度、完整资源限制、真实终态、进程清空及错误通道的验证方式。保留原 UID/GID、零业务能力、NNP、网络与文件隔离，不以关闭安全设置换取成功，不挪用旧轮次额度，不动失败现场或写锁。

新探针只用于确定启动阶段错误，不代替 LACK/Caddy 真实切换、数据库副本兼容、故障回滚及最终生产验收。
