# MCP-only 配置边界

状态：本地开发与隔离验证阶段，未部署、未授予外部 Agent 访问权限。

目标是在保留通用节点 REST 能力的同时，允许首次外部 MCP 试点独立关闭公网节点 REST。不增加常驻服务，不改变模型路由、Ollama、凭据或 Tailscale Relay。

## 配置

在现有 `publicRuntime` 对象中设置：

```json
{
  "nodeRestPublic": false
}
```

这是片段，不是完整运行配置。必须是布尔值，字符串 `"false"`、null、数值、数组和对象均被拒绝。省略或设为 true 时保留原正常模式。

| OAuth 发现模式 | nodeRestPublic | 公网 MCP | 公网 /v1 与 /v1/* |
| --- | --- | --- | --- |
| 开启 | 任意合法值 | 仅发现信息，业务仍拒绝 | 拒绝 |
| 关闭 | false | 仍须通过现有认证、范围和本地授权 | 拒绝 |
| 关闭 | true 或省略 | 原正常模式 | 原有节点认证与权限检查 |

HTTP 入口和后端网关共同拒绝转发的节点 REST 请求，即使携带有效节点凭据也不例外。内部未转发的回环节点 API 保留原有认证；并非匿名内部访问。网关仍只绑定回环地址，不能将它直接暴露到公网。

MCP-only 不自动启用 OAuth、增加客户端白名单、建立账户绑定、创建节点、授予工作区权限或启用事件。接入这些能力仍需分别获得明确授权。

## 启用流程

1. 完成新配置的本地、真实 HTTPS 和原资源限额 Linux 隔离测试。
2. 根据同一份配置生成并校验应用与 HTTPS 入口候选，不能只更改其中一端。
3. 按批准的维护范围备份、更新、检查和保留回滚路径。本文不构成生产发布授权。
4. 验证 MCP 无令牌被拒绝、合法授权可执行受限调用，公网所有节点 REST 路径仍为 404，内部回环继续要求合法节点身份。

不能仅凭路由文本、配置保存或 HTTP 200 声称 Muse/dots 接入完成；仍需其自身电脑执行、匹配任务随机码、原始证据和持久化回执。

## Windows 开发回归复现

使用 Node.js 24、Python 和已经核验的便携 Caddy；在独立 PowerShell 窗口中，将 `PYTHON`、`CADDY_TEST_BIN` 指向本机实际工具路径后运行：

```powershell
$env:GOMAXPROCS = '1'
npm test
if ($LASTEXITCODE -ne 0) { throw 'Regression failed' }
npm run smoke
if ($LASTEXITCODE -ne 0) { throw 'Smoke failed' }
```

`GOMAXPROCS=1` 只约束该终端子进程的 Go 调度并行度，不是 VPS 的 CPU 百分比配额，也不是 Agent 数量上限。不要设为机器级变量；关闭独立终端后该设置不持久保留。发生超时时先保留失败报告并定位阶段，不跳过 TLS/权限断言、不先增加超时，也不停止其他用户进程。

## Agent 授权首次迁移的发布门槛

截至 2026-10-18，本节已完成本地与隔离验证，未发布生产，未授予 Muse 或 dots 访问。完整记录见 [串行隔离验收](verification/2026-10-18-agent-authority-serial-acceptance.json)；此前失败记录仍保留，不能用本次通过覆盖其状态。

首次授权迁移需要操作者在发布控制器的私有 `settings` 中显式选择以下策略。它不是 `publicRuntime` 的配置项，以下也不是可直接替换完整配置的文件：

```json
{
  "releaseProfile": "mcp-only",
  "migrationContract": "agent-authority-v1"
}
```

- 省略 `migrationContract` 或设为 null 时，保持原有结构完全相等的严格门槛。未知值、错误 profile、已部分迁移的源库均拒绝；不能以修库、删表或删锁绕过。
- 首次迁移只接受独立冻结目录中的 17 个精确对象：2 张表、12 个触发器、3 个自动索引。原有结构和其他数据库不变，不能只检查对象名称。
- 私有副本验证原始记录、类型、空值和重复行均保留；组件版本仅允许两条预期的 version=1 新记录，membership epoch 正确回填，初始授权为零。策略本身不创建可用的外部访问授权。
- 故障事务回滚、故障后的旧版启动、候选启动、旧版读取迁移后数据及候选重复启动均须通过。普通后续发布面对已迁移库时，不重复使用首次迁移策略。
- 正式证明绑定候选与旧版代码、源结构、策略和相关非凭据配置，并由 `preparedHashes` 绑定证明文件。证明必须为私有、无符号链接的受限文件，且在一小时有效期内；停服务前校验，冷备份后再查源结构。不能长期复用本轮测试证明。
- 活跃 WAL 中仅出现组件版本记录、但表结构尚未完整迁移的源库，也须在停止服务前拒绝。不得仅检查主数据库文件而漏过 WAL。
- 回滚只接受原始结构或精确完整的迁移结构；保留用户新配置、上传和数据库新写入，不把历史数据库备份回灌覆盖现有数据。

### 隔离复验与串行演练

控制器完整回归命令见 [实施计划](superpowers/plans/2026-10-18-agent-authority-migration-gate.md)。本轮 Windows 43 项中 40 项通过、3 项仅适用于 Linux；Linux 43 项全部通过。三个历史真实数据库副本的正式迁移及证明绑定也已通过；副本不是新鲜生产一致性备份，不能据此直接切换生产。

生命周期脚本的最后一个可选参数为 `all`、`success` 或 `rollback`，默认 `all` 保留原两场景行为，未知值拒绝。受限环境使用两个不同的独占根目录和单元，按 `success`、`rollback` 串行执行；必须确认前一单元真实终止、MainPID=0、自有 cgroup 为空后再启动下一单元，不能并行叠加额度。

```text
python3 rehearse-operational-release-20261017.py <独占成功演练根目录> mcp-only agent-authority-v1 success
python3 rehearse-operational-release-20261017.py <另一个独占回滚演练根目录> mcp-only agent-authority-v1 rollback
```

以上是脚本参数说明，不是可脱离既有隔离运行器直接在生产执行的命令。目录格式、合成夹具及挂载仍须满足脚本原有要求。

- 每场景合计仍为 192 MiB、单核 10% CPU、32 Tasks：控制器 96 MiB / 5% / 16，两个夹具各 48 MiB / 2.5% / 8；每个单元仍限 90 秒，禁止增加超时或删断言。
- 控制器的前向 55 秒、总恢复 120 秒窗口不变。生命周期夹具使用高位回环 HTTP 和出口过滤，不冒充真实 TLS、私有网络命名空间或外部 Agent 验收；正式数据库副本验证使用私有网络隔离。
- 本轮成功与回滚单元的完整生命周期分别为 42.430 和 47.983 秒；事务部分分别为 22.934 和 28.686 秒。两单元不重叠，全部原断言保留。
- 新隔离 staged 父目录须显式为 `0750 root:987`，不依赖受 umask 影响的 mkdir 参数；先验证服务账号可遍历并读取候选模块。本次只修改新建独占目录，不修改任何既有目录或生产权限。
