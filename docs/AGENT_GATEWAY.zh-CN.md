# ChunLACK 外部 Agent 网关使用说明

## 本期范围

通用网关用于把其他机器上的研究 Agent 接入 LACK。节点自己调用本地或云端模型，LACK 负责分派任务和记录结果。它不是任意远程桌面、shell 或文件执行接口。

- 网关默认关闭，与 LACK 共进程；独立监听 `127.0.0.1`，独立鉴权。
- 不增加 npm 依赖、Redis、独立数据库服务或后台连接器服务。
- 默认最多 5 个有效节点，同时最多执行 1 个网关任务。
- 支持 `research.retrieve`、`research.verify`、`research.summarize`。
- Ollama 和供应商中立的内部模型路由保留；外部 Agent 委派不替代 Provider。
- muse.ai、dots、Codex、OpenClaw 的真实产品包装器尚未接通。SDK 是接入基础，不代表这些产品已经具有可用接口。

## 1. 启用网关

在现有 LACK 私有配置中合并以下字段，不要覆盖其他配置：

```json
{
  "agentGateway": {
    "enabled": true,
    "port": 13722,
    "adminTokenEnv": "LACK_AGENT_GATEWAY_ADMIN_TOKEN"
  }
}
```

端口只是示例，应选未占用的回环端口。运行 LACK 的进程环境必须提供对应管理员秘密，长度至少 43 个字符。使用密码管理器或私有服务环境文件生成、保存随机值，不要提交 Git、发送聊天、写入模型提示或 URL。

网关数据位于 LACK 数据根目录的 `db/agent-gateway.db`。配置错误或端口冲突时网关不可用，旧 LACK 服务应继续运行；不要据此认为外部节点已接通。

本期没有部署到 VPS，没有修改现有生产配置。远程启用、重启服务和真实节点接入应作为独立部署步骤。

## 2. 私有访问

服务器网关只监听回环地址。远端 Windows/Mac 应通过已经授权的 SSH 转发或经过审核的私有 TLS 入口访问，不要开放公网端口。

示例 SSH 转发：

```sh
ssh -N -L 13722:127.0.0.1:13722 <user>@<private-host>
```

本地访问 `http://127.0.0.1:13722/admin`。管理页输入管理员凭据后连接，凭据只保存在当前页面内存；关闭或退出后需要重新输入。

SDK 允许 HTTPS 或本机回环 HTTP，拒绝普通局域网地址的明文 HTTP。Tailscale 私有地址不是回环地址，不能直接作为明文 SDK 入口。

## 3. 配对节点

1. 管理页创建节点，选择能力和作用域。首期使用 `public` 作用域，只发送公开非敏感研究资料。
2. 取得一次性配对码。有效期 5 分钟，只能使用一次。
3. 节点安装 Node.js 24，取得本仓库的 `sdk` 目录，在交互终端执行：

```sh
node sdk/cli.cjs pair http://127.0.0.1:13722
node sdk/cli.cjs status
```

配对码通过不回显输入读取，不作为命令行参数。凭据保存到当前用户家目录的 `.chunlack/connector.json`。Windows 检查专属 ACL，POSIX 检查所有者和权限；保护失败时拒绝保存。不要把该文件放进 Git、共享目录或公开备份。

配对码丢失或过期时从管理页重新配对。重新配对会使旧节点令牌失效。管理员令牌与节点令牌不能混用。

## 4. 模拟节点与真实包装器

运行明确标为模拟的前台节点：

```sh
node sdk/cli.cjs run --fixture
```

模拟 handler 只接受带 `fixture: true` 的测试输入，不调用真实模型。按 `Ctrl+C` 停止；没有自动安装系统服务。

真实包装器应由本地受信任代码调用 `AgentClient.run(handler, {signal})`。handler 接收任务、取消信号和进度上报函数，返回结构化结果。包装器自行管理本机模型地址、密钥和调用策略，不把密钥发送给 LACK。

任务不能指定动态脚本、任意模块或主机命令。支持取消的包装器应把 `signal` 传递给自身模型请求。对已提交的外部服务，取消信号不保证服务实际停止或不产生费用。

## 5. 研究角色配置与证据限制

内部角色仍使用现有 Agent ID。外部角色使用管理页生成的节点 ID，例如：

```json
{
  "researchPublicOnly": true,
  "researchRoles": {
    "retriever": "internal-retriever-agent-id",
    "verifier": {"kind": "external", "nodeId": "NODE_ID_FROM_ADMIN"},
    "summarizer": "internal-summarizer-agent-id"
  }
}
```

三种角色应保持不同身份，节点需声明对应能力。启用外部阶段必须显式允许公开研究；`localOnly` 或未明确允许的资料不得委派外部节点。

外部检索返回的 URL、原文和声明仍标为未核验。节点提供的摘录不能证明网页真实存在，也不能绕过原有证据门禁。目前外部检索会等待独立取得原始来源，不是完整自动检索闭环。验证阶段拒绝伪造摘录、缺失或未知结论 ID；汇总仅整理已支持结论，缺证仍须保留。

## 6. 管理与故障处理

- 在线状态只说明最近有通信，不说明模型可用或结果正确。
- 暂停停止新派单，不保证已经开始的工作停止。
- 撤销使节点凭据失效，晚到结果不得作为新结果接收。
- 取消请求与取消确认分别记录，不能把请求发送成功当作远端已经停止。
- 租约默认 90 秒，执行时约每 30 秒续租；超时进入需要人工处理，不自动交给另一个节点。
- 重试前确认旧工作已停止，避免重复调用和重复费用。
- 相同事件 ID、相同内容重试可重复返回确认；相同 ID、不同内容属于冲突。
- 任务和结果页可查看状态及结构化结果；管理员凭据不要出现在截图中。

请求正文上限 256 KiB，检索结果最多 5 个来源、25 项结论。队列、事件和数据库增长均有限制，不能作为无限日志存储。

## 7. 验证范围

当前本地模拟测试覆盖配对、权限、租约、撤销、结果去重、凭据保护及研究证据边界。Windows 凭据 ACL 已在本机测试；macOS 原生运行、真实模型、真实第三方包装器和 VPS 资源上限尚未验证。

五节点测量使用同一个本地进程内的网关和模拟客户端，不能直接推导 2C2G VPS 的持续安全上限。资源测量数据应以单独验证记录为准。

## 8. 停用与清理

把 `agentGateway.enabled` 改为 `false` 后，按已有维护流程重新启动 LACK。先停止各节点前台进程和 SSH 转发。需要删除节点凭据或数据库时，先确认不再使用并备份必要记录；不自动删除现有数据或修改系统服务。
